# 名局の戦場（chess-battle）企画書（案・批判役の指摘を入れた版）

2026-10-31 〜。チェスの古い名局を、本物っぽい3Dの戦場に書き起こして、ドラマチックに見せる。
英語名（案）: The Battlefield of Great Games

## ねらい
- **いちばんのねらい（2026-10-31 ユーザー）: 見た人が「チェスかっこいい！やりたい！」（将来は将棋も）と思うこと。** リアルさ・演出はそのための手段。迷ったら「かっこいいか・名手のすごさが伝わるか」で決める。最後に駒の動き方・始め方の入口へつなぐ（自分で指す機能は作らない）。
- 盤の上の「1手」が、戦場では「部隊の動き」になる。サクリファイス（駒をわざと捨てる）と最後の詰みを、映画のように見せる。
- **棋譜は本物（記録）、戦いのようすは演出（想像）**。この区別を画面にはっきり書く（RULES 9章）。
- 部隊が動くマスは棋譜どおり。見た目のために手やマスを変えない。

- 棋譜は当時の出版物と照合用のサイトの両方を出どころに書く。版のちがいがある局（不滅の一局）は、使った版を画面に書く。

- 実在の人は事実だけ。顔・姿は描かず、名前は戦場の旗ではなく盤の外の札（「白: モーフィー」）に出す。

## 見る人の手がすること・時間の見せ方（RULES 4章）
- **ながめる**が中心。「つぎへ」1つで最後まで進む。ただし **1回 = 1つの場面**:
  - 序盤の駒を出す手は数手まとめて早送り。捨て駒・取る手・チェックの前で止まる。
  - スライダー1本（白黒それぞれの手を1目盛り）。見せ場に印。どの手へも飛べ、巻き戻すと部隊も戻る。
- 捨て駒の直前に、王をねらう線を光らせる（chess.js で計算。※ 目印）。捨てたあとの1〜2手で「なぜ得なのか」を見せる。
- 駒の損得の帯（白黒の点数）で「損しているのに勝つ」を目で見せる。
- カメラ: おまかせ（演出）／自由に動かす／真上（ふつうの盤）。
- 自分で手を指す機能・予想の当てっこは作らない（勝ち負けや点数を付けない → ゲームではない。RULES 8.3）。
- 形勢の評価に Stockfish は使わない（GPL）。見どころは手で書いた文で。

## 見せ方の芯（2026-10-31 ユーザー。段階Aのあとに決めなおした）
- **盤の上でコマをチマチマ動かす見た目にしない**（それでは「チェス＝盤の遊び」という今のイメージから抜けられない）。
- **大きな画面＝指している人の頭の中の戦場**。マス目は見せず、丘・森・野原の本物らしい地形に両軍が布陣する。1つのコマは4〜9人の部隊（スマホでも動く人数。いつか増やす）。カメラは地面の高さ・上空から映画のように。
- **隅の小さな盤＝現実の盤**（人の手もと）。「盤の1手が、頭の中ではこんな戦いになっている」を並べて見せる。
- 動きは作戦として: 進む＝行軍、ナイト＝騎兵が側面へ回りこむ、取る＝突撃とぶつかり合い。部隊の居場所は棋譜のマスに対応させる（地形の上の陣地として。マス目の線は見たい人だけが出せる ※ 目印）。
- 兵は人の速さで動く（歩く 約1.4 m/s など）。長くかかるところは「×4倍速」のように画面に書いて早める。
- 駒の由来（チャトランガの4つの兵種＝部隊、キング・クイーン（もとは相談役）＝1人）を「このアプリについて」に。クイーンは「1人の大臣と護衛」にする（チャトランガの mantri＝大臣。Wikipedia で確かめた）。

## 段階Bの途中のユーザーの指摘（2026-10-31）と決めたこと
指摘: ①隊がかたまって動くのでコマ感がぬぐえない ②ターン制のように交互に動くのでリアルな戦場に感じない ③絵とモーションがチープ ④退場がのんびり歩いて出ていくので違和感。
→ 前もって描いた動画（Blender）ではなく、**その場で描く（A）を続ける**。理由（ユーザー）: **見る人が自分の棋譜ファイルを選んで読みこみ、動かす遊びもさせたい**。どんな対局でもその場で戦場にできる必要がある。
- ① 兵を1人ずつ動かす: 1人ずつ自分の速さ・道・間合いを持ち、よけ合う（群れの動き）。突撃で隊形がくずれ、ぶつかり合いは散らばった小ぜり合いに。1隊の人数を増やす（数十人）。
- ② 戦場はいつも動いている: chess.js の「どのマスをねらっているか」から、ねらい合う前線では小ぜり合い・矢がいつも続く。1手は「その中の大きな動き」。前の動きが終わる前につぎが始まる。
- ③ 絵と動き: three.js を新しい版（0.185.1）にし、兵は InstancedMesh2（MIT）でまとめて描いて数百〜千人に。光と空気（もや・土ぼこり・ぼかし）、草の地面と空（Poly Haven など CC0）、動きのつなぎ目をなめらかに。
- ④ 取られた隊は「敗走」にする予定だったが、**ユーザーの指示（2026-10-31）で「その場で気絶して、少し薄く表示して残す」**に変えた（敗走で画面が見づらくなるより、現実にはありえない薄さのほうがよい）。倒れる動きは素材の Death01（画面の言葉は「気絶」）。血はなし。画面に「※ 見やすさのため薄く表示」。
- **棋譜ファイルの読みこみ（段階D を前倒しで設計に入れる）**: PGN を選ぶ・貼る → その場で戦場に。ファイルは端末の中だけで使い、どこにも送らない。解説の文は自動（autoNote）、名局のような手書きの解説はない。読めない棋譜は理由を出す。
- 正直さ: 兵の数・速さ・小ぜり合いは想像（演出）。動くマスと順番は棋譜のとおり。

## 人から海戦へ（2026-10-31 ユーザーと決めた。見本で見くらべてから切りかえる）
ユーザー: Web では人の兵はチープさが出て、作りこむとスマホで重い。別の生き物や機械でも、リアリティを出せて納得感のある置きかえなら振り切ってよい。→ **帆と蒸気の時代の海戦**。
- 理由: 船は硬い物なので、光と材質（木・鉄・帆布）が正しければ本物らしく見える。1駒1隻で32隻だけ描けばよい。海・空・霧は Web でいちばん本物らしく出せる景色。オペラ座の一局（1858）は帆から蒸気へ移る時代そのもの。
| 駒 | 船 | 動き方の納得感 |
|---|---|---|
| ルーク | 蒸気船 | 風に関係なくエンジンでまっすぐどこまでも |
| ビショップ | 帆船 | 風に向かってまっすぐ進めず、ななめに進む（間切り）。盤の縦の向きに風という見立て。※ 本当に進める角度は風に対して 60° 前後（画面に注記） |
| クイーン | 帆と蒸気の両方を持つ艦 | ルーク＋ビショップ。1850〜60年代の軍艦の形 |
| ナイト | 潜水艦 | 潜ってほかの船の下をくぐり浮上＝飛びこえる |
| キング | 旗艦 | 大きく重く1マスずつ。失うと艦隊が負ける |
| ポーン | 砲艇 | 大砲が船の横にあるので、真正面は撃てず、ななめ前の敵だけ撃てる。前へだけ |
- 取られた船: 白旗を上げて止まり、薄く表示（沈む・血はなし）。大砲の煙と水しぶき。
- 将棋版へ: 飛車＝蒸気船、角＝帆船、桂馬＝潜水艦、香車＝魚雷艇、王＝旗艦、持ち駒＝拿捕した船に味方を乗せて艦隊に入れる（実際の海戦でもあったこと）。
- 素材: Poly Haven（CC0）の dutch_ship_large_01・02・medium（17世紀のオランダ船。※ 1858 年より古い形と画面に書く）、cannon_01。蒸気船は CC0 の本物らしいものがないので Blender で組む。
- 海の描き方（くらべた）: three の Water（映りこみで2倍重い）／自分で書くゲルストナー波＋空の写真の映りこみ（軽い。船の上下も同じ式）／wave-growth の FFT（本物らしいが three とつなぐのが大がかり）→ まずゲルストナー波で見本。

## 盤を戦場に置きかえる決まり（人の兵のころのもの。2026-10-31 に海戦へ切りかえたので、いまは上の「人から海戦へ」と index.html の「駒と船の対応」が正）
- 8×8 のマス → 地形の上の 8×8 の陣地（線は見せない。※ 目印として出せる）。
- **取る = そのマスへ攻めこむ**（どの部隊も同じ。離れたところから射て取ることはしない）。
- 駒 → 部隊（最初に対応表を1枚出し、真上モードでも同じ表を見られる）
  - キング: 指揮官の旗の一団。クイーン: いちばん大きな部隊。ルーク: 盾をならべた重い兵（攻城塔はやめる。端から端まで1手で動くのと合わない）。ビショップ: 斜めにだけ進む弓兵の隊（射るのは飾りだけ）。ナイト: 騎兵（ほかの部隊を飛びこえる）。ポーン: 歩兵の小隊。
- **子ども向けの線引き**（2026-10-31 ユーザーの指示で変更）: 取られた隊はその場で気絶して倒れ、見やすさのため半透明で残す（※ 画面に注記）。入れないもの: 血、悲鳴、武器が刺さる寄りの絵、炎、「死」という言葉（画面の言葉は「気絶」）。チェックは王の隊が構える。チェックメイトは王の旗が倒れる。
- キャスリング（12.O-O-O）はオペラ座の一局で出るので A〜C で作る。成り・アンパッサンは3局とも出ないので、出る局を足すまで作らない（verify.js で局ごとの特別な手の一覧を確かめる）。

## 画面（スマホから考える。RULES 9章）
- 上に固定: 戦場の3D（縦長では上半分）＋**隅に小さな盤（約 90px。動いたマス・取られたマスを光らせる）**＋いまの手（例「16. Qb8+!! クイーンを捨てる」）。
- 縦長のおまかせカメラは「寄り」が基本、ときどき引いて全体。
- 下にスクロール: 損得の帯・手の一覧・解説・「このアプリについて」（おもな出どころ・演出の注意）。
- ボタンは 36px 以上。

## 段階
- **A 骨組み**: three.js の版を決めて lib/ に置く（GLTFLoader を使うので、r128 のままか新しい版の ES モジュールか、ここで決める）。chess.js で棋譜を読み、全局面を作る。平らな大地に箱の部隊、場面ごとのつぎへ・スライダー・巻き戻し・隅の盤・手の一覧・損得の帯。**確かめ**: 最終局面と特別な手の一覧（`tools/verify.js`）。
- **B 皮ふ（見た目）**: **はじめに絵柄の方向を見本2案で選んでもらう**（写実寄り／これまでの紺と線の図寄り）。地形・空・霧・兵士・旗。**B に入る条件**: 部隊あたりの兵の数の上限を決め、幅375px の端末で 30fps（兵の動きは焼きつけた頂点アニメーションか、遠くの兵は動かさない LOD。InstancedMesh はそのままでは骨の動きを使えない）。
- **C 演出**: カメラの監督（場面の種類でカット・寄り・スロー）、攻めこむ場面、キャスリング、チェック・詰み、音（効果音＋BGM。おとライブラリ。AI-MUSIC 4章を先に）。
- **D 名局を増やす**: 不滅の一局・常緑の一局、対局の選択。英語対応（入口へ移すとき）。
