## しくみ
- 部隊の id は初めの局面の駒から（`wNb`＝白の b のナイト、`wK`＝白のキング）。手ごとに from→to で動かし、取られた部隊は `sq=null`・`out`＝取られた順。キャスリングはルークも動かす。追跡が chess.js の局面と全手で同じことを verify で確かめる。
- 場面: 取る・チェック・キャスリング・見せ場（games.js の key・sac）は1手で1場面、静かな手は4手までまとめて早送り（1.7倍）。オペラ座の一局は 33手 → 22場面。
- マス → 3D: 1マス 8 m、a〜h が x、1〜8 が z（白が手前の +z）。高さは `height(x,z)`。取られた部隊は白が戦場の左の外、黒が右の外へ退く。
- 兵の描き方: 兵は骨を持たない SkinnedMesh で、見本の骨組み（モデル2×動き7×位相4）を `bindMode="detached"` で共有する。動きを変える＝`mesh.skeleton` を別の見本にかえる。見本は原点に置き、毎コマ mixer と骨の計算を1回だけ。250人で 1コマ 42ms → 約18ms（この PC。crowd-test で測った）。アプリでは 196人で計算 約2ms・描く 約7.5ms（375px）。
- 服の色: 色の絵の左下 1/4（glTF の uv で u<0.5・v>0.5）が服。シェーダーで明るさを残して白軍＝白、黒軍＝赤に塗りかえる（army.js の onBeforeCompile）。
- 速さ（army.js `SPEED`）: 歩く 1.4・小走り 3.5・全力 6.0 m/s。ポーン・キングは歩く、ナイトは全力、ほかは小走り。取る手は最後の1マスぶんを全力で突撃。画面は `TIME`=2 倍速（動きの絵も同じ倍率なので足がすべらない）。
- 取る場面（army.js `playPly`）: 攻める隊は前の列が触れない距離まで突撃 → 剣をふる（1.6 秒。0.5 秒で `V.struck`）→ 相手が 1マス離れたら陣地へ。取られる隊は止まる位置を向いて構え → `struck` で旗を下ろす（降参）→ 1マス後ろへ → 横へ → 戦場の外（倒れない・打たれる動きなし）。詰みは詰まされた王の旗が下りる。退く部隊は `busy()` に入れない（待たずにつぎの手へ）。
- カメラ: おまかせ＝動いている部隊のうしろ 14 m・高さ 6.5 m から追う（縦長は少し遠く）、止まっているときは白の側から全体。真上＝画面の上が黒（`up=(0,0,-1)`）。自由＝OrbitControls。
- 駒の点数は P1・N3・B3・R5・Q9（よく使われる目安）。オペラ座の一局の最後は白 15・黒 25（損しているのに勝つ）。

## 批判役との話し合い（2026-10-31 段階B）
- 直した: 打たれる動きをやめ「構える → 打ちこまれたら旗を下ろす（降参）→ 後ろへ下がって退く」に。前の列が触れない距離で止まる（2つの隊の奥行き＋1.5 m）。待ち合わせは「打った」の合図＋待ちの上限。ナイトはマスのさかいを通る L 字、取ったあとは相手が 1マス離れてから入る、キャスリングはルークが先。画面に「本当の盤」「頭の中の戦場（想像）」の札と駒の点数。手の記号（!・!!）。詰みで王の旗が下りる。隅の盤は動き終わるまで前の局面。旗の裏を正しい向きに。視野の外の兵は描かない・スマホでは兵の影なし。もどるは場面の初めへ。
- 段階Cへ: 捨て駒の前に止めて王への線を見せる、チェックの合図、詰みでビショップとルークを順に映す、カメラの向きの扇形を隅の盤に、隅の盤のマスを押すとその隊へ寄る。
- 直さない: doctype（このリポジトリのアプリは doctype なしで作る決まり。new-app.ps1）。
- **ユーザーに決めてもらう**: 剣をふる動き（いまは素手で空を切る。相手には当たらない）でよいか。

## 批判役との話し合い（2026-10-31 光と草のあと）
- 直した: 気絶した兵が消えていた（opacity 0.4 と alphaTest 0.5 の組み合わせで全部捨てられる → alphaTest 0）。2回目の突撃で触れる前に相手が倒れる（contactT のリセット）。並びなおしは長くても8秒。倒れる位置は id からの乱数（飛んでも同じ）。兵が足りないときは __chbaErr に。止まる↔歩くのしきい値に幅。矢は弓兵（ビショップ）だけ。木を回さない（日の当たる側がそろう）。カメラは長く止まったときだけ全体へ引く。スマホ判定に pointer:coarse、草 1.5万本、影 1024、気絶用の骨は置いたときだけ送る。出どころ（Poly Haven・bvh.js）と速さの文。
- 次の区切りで: 前の動きが終わる前につぎの手を始める（active を配列に）、動きの絵をまぜてつなぐ・歩く絵の速さを実際の速さに合わせる、武器・盾・弓、白の服の色の見本、気絶の薄さの見本2案（ゆっくり薄く・地面の色へ）、空の解像度、木の絵の切りかえをまぜる、地平線のもや、スマホの足もとの影、止まっている兵の小さな動き、取ったマスで倒れた兵の上に立つ、飛んだときの倒れた旗。
- 棋譜ファイルの読みこみのとき: [FEN]・SetUp から始まる局（replay も同じ FEN から、id を通し番号に）、成り（隊を作りなおす）、アンパッサン（相手のいるマスへ突撃）、Chess960 のキャスリング、長い局（静かな手を同時に・倍速を上げる）、投了・時間切れの終わり、1ファイルに何局か・変化手順・コメント、読めない手の知らせ方。

## ハマったところ
- **InstancedMesh2 の骨の情報は `boneTexture.enqueueUpdate()` で送る**。three のふつうの `needsUpdate=true` では送られず、兵が最初の姿勢のまま固まって「直立不動ですべる」ように見えた（ユーザーの指摘で気づいた）。いまは `partialUpdate=false`＋毎コマ `enqueueUpdate(0)`。crowd-test2 の千人の速さ（描く 17.3ms）もこの状態で測っていた。
- 企画の段階で「キャスリングは 10手目」と書いていたが、棋譜では **12.O-O-O**（verify で確かめた）。手の番号は記憶で書かず verify で。
- おまかせのカメラを手番の側から見るようにしたら、手ごとに盤の向きが入れかわってわからなくなった → いつも白の側から。
- 真上のカメラは真下を向くと上の向きが決まらず、盤が回って見えた → 真上のときだけ `camera.up=(0,0,-1)`。
- 同じポート 8765 のサーバーがほかのセッションで動いていると preview_start が失敗する → そのまま navigate で開ける。

- Blender で兵士を作るとき: ①体のメッシュの名前は `SuperHero_Male`（データ名が `…Retopology…`）②見えない補助の形（Icosphere）が混ざっていて join が失敗する ③顔の表情の形（シェイプキー）があると Decimate を適用できない → それぞれ build-soldiers.py で処理ずみ。
- itch.io の無料ダウンロード: 内蔵ブラウザで「No thanks」→ Download。ページを移ると `~/Downloads` に `<uuid>.tmp` のまま残ることがある（中身は完全。unzip -t で確かめて名前を付ける）。
