# 電波の見える部屋 開発メモ

最終更新: 2026-11-04

WiFiの電波が家の中をどう伝わり、壁でどう弱まるかを真上から見るアプリ。体内ダイブ系とはエンジンが別（Three.js なし、WebGL2 を直接使う）。

## しくみ

- **計算**: 床に垂直な電場 Ez の2次元波動方程式 `∂²E/∂t² = (1/με)∇²E − (σ/ε)∂E/∂t` を陽解法で解く（TM モードなので Ez だけで厳密）。1マス `DX=0.75cm`、1280×800マス（9.6m×6m）、クーラン数 `KC=0.5` → 1ステップ `DT=12.5ps`。
- **GPU**: 状態テクスチャ RGBA32F を2枚でピンポン。`r=u(n)`, `g=u(n-1)`, `b=u² の指数移動平均（BETA=1/256）`。`EXT_color_buffer_float` が必須。材料は R8 テクスチャの ID（0 空気〜7 水・人体）で、シェーダは uniform 配列 `uK2[id]`（= KC²/εr、金属は −1 で Ez=0）と `uA[id]`（= σ·DT/2ε）を引く。
- **吸収境界**: 外周40マスのスポンジ（減衰係数を3乗で増やす）。`uStrip=1` のときは左右だけ（1次元テスト用）。
- **波源**: 点（ルーター）か、x=一定の線（平面波。「比べっこ」「すき間」）。開始時に2周期かけて立ち上げる。
- **dBm 換算**: 起動時に 320×320 の空の場で自由空間の `C = 平均(u²)·r` を測る（`CAL`）。受信 = `20dBm − FSPL_3D(d) + 10log10(平均u²·r / C)`。つまり2次元の「1/r」の広がりを3次元の自由空間損失に置き換え、壁・反射・干渉の分だけをシミュレーションから取る。平面波のときは基準の通路（何もなし／板なし）との差を出す。
- **材料の値**: ITU-R P.2040 の εr・σ（`MATS` の `er,c,d`）。表示する「壁1枚で −X dB」は `slabDb()`（垂直入射の板の透過を複素数で解析計算）。
- **格子の補正 `eff`**: 0.75cm 格子では 5GHz のガラス内が1波長3マスしかなく、そのままだとガラス −14dB・コンクリート −59dB と過大になる。そこで材料ごと・周波数ごとに、1次元テスト `__ww.stripDb(f,id,er,sig)` で「解析値と同じ透過損失になる εr・σ」を二分法で求め、`eff:[[2.4GHzのer,σ],[5GHzのer,σ]]` に固定した。材料を足すとき・厚さを変えるときは作り直すこと（コンソールで数秒）。2026-10-07 に確かめ直した: 5材料×2周波数すべてで `stripDb(eff)` と `slabDb` の差は 0.01dB 以内（例: コンクリート 2.437GHz 13.37dB、5.2GHz 23.01dB）。補正なし（ITU の値のまま）だと、5.2GHz でガラス 14.4dB・レンガ 7.3dB・コンクリート 59.1dB と過大になるのも、上の記述どおり。
- **画面**: 表示シェーダ1枚。波モードは `u / sqrt(2C/r)`（距離補正あり）を tanh で色に。強さモードは u² 平均を λ/2 の円内16点でならしてから dBm → 色。アンテナ本数の境目（−55/−67/−75/−85）に線。上に 2D キャンバス（部屋名・ルーター・スマホ・通路の値・作図プレビュー・縮尺）。
- **スマホ**: 17×17マスの平均を `readPixels` で読む。通路のプローブは 200×40マス（1.5m）平均（通路内のモードのうなりで数dBぶれるため）。電波が届くまで（距離/KC×1.25+700ステップ）は「待っています」。

## WiFi センシング（`js/sense.js`・`js/sense-ui.js`。企画は `PLAN.md`）

- **しくみ**: メインの画面とは別の小さな格子（800×500マス＝6m×3.75m。段階Aでは 640×512、段階Bで地図と同じ形に。外周40マスのスポンジは同じ）で、同じシェーダ `SIM_FS` を回す。波源は 2.437GHz にのせたガウスのパルス（τ=2ns、直流なし、幅約150MHz）。毎ステップ、小さなシェーダ `PROBE_FS` が受信点＋部屋の15点の Ez を時系列テクスチャ（4096×192、1行に256ステップ×16点）に書き、2048ステップごとにまとめて readPixels。15点の Ez² の和がピークから −55dB に下がったら止める（いまの部屋で 8192 ステップ）。受信と送ったパルスを同じ52周波数（±1〜±26 × 312.5kHz、11a/g の並び＝ESP32 の LLTF）で DFT して割ったのが CSI `H`。
- 部屋 `SROOM`: 5.1m×2.85m。上（ガラス窓あり）と左がコンクリート、右（木のドアあり）と下が石こうボード。ルーター (0.85,0.85)、受信機 (5.1,2.9)。人は `personM` と同じ楕円（`sPerson`）、肩は歩く向きに直角（1回に6°まで回る）。`empty:true` で壁なし。
- **画面（2026-11-05 に作り直し）**: 間取り「人がいると」を選ぶと `S.sense`。`draw.js` の `loop` は `senseFrame()` だけを回す。パルスそのもの（`display(ssim)`）は1歩目に1回だけ、最初の 3200 ステップを1コマ16ステップでゆっくり見せる（この回が誰もいない部屋の測定。地図をタップするともう一度）。ほかのときは、最後に終わった測定から取り出した 2.437GHz の止まった波（`sDisplay` の 0、位相をゆっくり回す）か、誰もいない部屋との差（`sDisplay` の 1、半波長の円で |H|² を平均して dB の差、±6dB でだいだい／むらさき）。1回ごとに光って消える点滅はなくなった。誰もいない部屋はドアを開けた形で測り、人は開いたドアから入る（ドアの差が人の差にまざらない）。右の「表示・周波数・時間・壁を描く」と受信カードは `body.sense` で隠し（`.hide-sense`）、解説の `.sense-only` を出す。地図の下 `#senseBox` に棒と帯・判定・ツアーの文・ボタン（縦のスマホでは地図といっしょに上に固定）。「つぎへ」は地図の右上（`placeTour()`）。
- **時間**: 1回の測定ごとに人は 1.5cm 歩く（`STEP_M`）。本物を秒速1m・1秒に約67回の測定とみなし、測った回数の速さから「本物の約1/○」を出す。
- **雑音（推定）** `NOISE`: 1回ごとに全体のとび（AGC）0.5dB、52本それぞれに 5%。目安は Wang ほか（DeepFi、arXiv 1603.07080。本文で確かめた）の「止まった部屋で CSI の強さの標準偏差の 90% は平均の 10% 以下」（Intel 5300）。
- **判定** `MOTION`（win 20・group 26・k 3）: 1回ごとに平均で割って AGC を消し、52本を半分ずつ2つにまとめ、直近20回の分散を、雑音だけのときの分散（`calibrate()`、雑音のモデルだけで300回）と比べる。決め方（2026-11-04）: 雑音のない CSI を5本の歩く道（各 100〜200回）で記録し、雑音を5回のせて設定を比べた。10回・4グループ・3倍だと歩いて 7〜78%、20回・2グループ・3倍で 90〜98%、止まった人では 0%（最大 ×2.3）。1グループ（52本ぜんぶ）だと AGC の割り算で消えてしまう。
- **確かめ（2026-11-04、`tools/sense-verify.js`）**:
  1. 何もない所（0.8〜3.2m）: 振幅は 2次元の 1/√r と 0.04dB 以内、52本の中の差 0.05dB 以内。遅れは距離/c より 1.4% 長い（0.75cm 格子の数値分散で群速度が遅れる分。理屈の見積もりと同じ大きさ）。
  2. 部屋の中（人なし・2か所）: パルスの CSI の中央が、連続波の計算（`cwAt`、24000 ステップ）と 0.02dB・0.2°以内。
  3. 打ち切りを 1.5倍にしても 52本の差は 0.04dB 以下。
  4. 人を 1マス（0.75cm）ずつ動かすと、1マスの変化は 52本の平均で 0.1〜0.33dB、12cm で空の部屋との差 3.8dB。つながりは切れない → 時間の見せ方は「1回に1マス歩かせる」（PLAN の案 (b)）。
  5. 1回の時間: PC で 0.12〜0.37秒（Browser ペインが隠れた状態。ばらつく）。スマホは未測定。
  6. 2.437GHz の地図（2026-11-05）: 受信機のマスで、地図の値（4ステップごとの和 ÷ パルスの和）が連続波 `cwAt` と 0.005dB・0.0001rad、両どなりの周波数（±1）とも 0.003dB で合う。地図の和を足して1回の時間は約15%のび（同じ条件で 218→252ms）。
- 気づいたこと: 2次元なので、人が受信の真ん前（見通しの線の上）に立つと −15dB も落ちる（柱の影。本物の人より大きく出る）。部屋が小さく響きが短い（〜100ns）ので、20MHz の中のでこぼこは小さい（人なしで 1.4dB の幅）。本物の雑音（1〜2dB の見こみ）より1マスの変化は小さいので、判定は何回分かのゆれで見る必要がある（段階B）。
- 2026-11-04 段階B のあと 800×500 の格子で測り直し: 自由空間は同じ、部屋の中のパルスと連続波の差 0.05dB・0.27°以内、N と 1.5N で 0.08dB 以内、PC で1回約0.12秒（`tools/sense-verify.js`。ほかの間取りを開いた状態で読みこむ。「人がいると」の画面の最中は測定と食いあうので使わない）。
- 材料の `eff` は 2.437GHz のまま使う。20MHz の幅の中で値は変えていない。位相と斜めの入射は合わせていない。

## 確認のしかた

ビューが隠れているとアニメーションが止まるので、コンソールで `__ww.advance(n)`（nステップ進めて描画・読み取り）を使う。GPU なら 4500 ステップは一瞬。

1. 読み込み直後にエラーなし（`window.__wwErr` が空）。`__ww.CAL` に 2.4/5 の `C`・`L` が入る。
2. 「壁の比べっこ」で 4500 ステップ後、通路の値が解析値（ツールボタンの数字）と ±1.5dB 程度。目安（2.4GHz / 5GHz）: ガラス −3.9/−3.0、石こうボード −3.3/−1.8、木 −1.2/−1.9、レンガ −4.0/−3.7、コンクリート −14/−23、金属は「届かない」。
3. 「すき間の実験」: 4cm が 2.4GHz で約 −30dB、5GHz で約 −14dB。2cm は両方とも届かない。
4. 2LDK: スマホ（LDK窓際）が 2.4GHz で約 −48dBm、「壁がなければ −38dBm」、間の壁は「石こうボード×2」（木造の一戸建ても ×2）。ルーターをドラッグで動かせる、材料を選んでドラッグで壁が描ける、元に戻すが効く。
