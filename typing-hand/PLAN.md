# タイピングする手 企画書

作成 2026-10-17

## ユーザーの依頼
「ピアノを弾く手アプリを流用してタイピングする手アプリを作れないか？」「勝手にタイピングしているのを眺めるモードと、ユーザーが打ち込んだものを再現するもの。指運びの参考データがあれば使いたい。なければあくまでコンピュータで導き出したシミュレーションだということを強調しておいて」（2026-10-17）

## 答え（できるかどうか）
- **できる**。手（骨格・皮ふ・筋肉の模型・関節の計算・肌の描画）は `piano-hand/` のものがそのまま使える。作り直すのは、キーボード（寸法と見た目）・指の割り当て・入力（楽譜 → 文字）・手首の解き方（ピアノはほぼ横だけ、タイピングは奥と手前の段へも伸びる）。
- **指運びの参考データは使えない**（2026-10-17 に調べた）:
  - Feit, Weir, Oulasvirta "How We Type"（CHI 2016）のデータ: 30人のモーションキャプチャ（52点・240fps）と、どの指で打ったかつきの打鍵の記録。いちばん合っているが、Zenodo の記録の利用条件が **CC BY-NC 4.0**（商用は不可）。
  - Dhakal ほか "Observations on Typing from 136 Million Keystrokes"（CHI 2018）のデータ: 打鍵の時刻だけ（指はなし）。利用条件は研究と商用でない利用だけ。
  - このサイトは収益化の可能性があるので、商用を禁じたデータは使わない（RULES・メモの決まり）。商用可（CC BY・CC0）で、物理キーボード・指つきのデータは見つからなかった。
- そこで、**指運びはコンピュータで計算したシミュレーション**とし、画面のいちばん目立つ所にそう書く（下の「シミュレーションだと伝える」）。
  - 論文の**本文に書かれた結果**（例: ふだんの打ち方では使う指が少ない人も多い、など）を説明の参考に引くのは、データを写すこととは別。使うときは原文で確かめてから、出どころを画面に書く。データそのものの数値は写さない。

## ねらい
- 文字を打つとき、10本の指がどう分担して、手首がどう動いているかを見る（ふだん自分の手は見ていない）。
- 自分が打ったものを手が打ち直すのを見て、「こう動いているのか」と気づく。
- 骨・筋肉を透かして見られる（ピアノと同じ「見せ方」）。

## 2つのモード
1. **ながめる**: 手がひとりでに文章を打つ。文はこのアプリで書いた短い文（ローマ字入力）。速さを変えられる。カメラは自由に回せる。
2. **再現する**: ユーザーが自分のキーボードで打ったキーを、押した・離した時刻のとおりに画面の手が打つ。
   - 打っている最中に少し遅れてついてくる表示と、打ち終わってから再生する表示。
   - 読むのは**どのキーを押したか（物理キーの位置 `KeyboardEvent.code`）と時刻だけ**。文字の中身は使わない・保存しない・送らない（`localStorage` にも入れない）。画面に「打ったものはどこにも保存・送信しません。パスワードなどは打たないでください」と書く。
   - 日本語入力（IME）がオンでもキーの位置は取れるので、そのまま動く。
   - スマホ・タブレットには物理キーボードがないことが多いので、画面のキーボードをタップして打てるようにする。スマホでは「ながめる」が中心。

## シミュレーションだと伝える（ユーザーの指示）
- 画面の上（図のすぐ下）に、いつも見える一文: 「この指の動きは、コンピュータが計算したシミュレーションです。実際の人の指の動きを測ったものではありません」。
- 「再現する」でも、再現しているのは**押したキーと時刻だけ**で、どの指で押したか・手の形は計算したものだと書く（ユーザーが実際に使った指は分からない）。
- 説明の欄に、計算のしかた（標準の指の割り当て、関節の届く範囲、指どうしがぶつからない、手首の動きが小さくなるように）を短く。
- 紹介動画・SNS の文にも同じことを書く。

## 指の割り当て（計算のしかた）
- 基本は**ホームポジションからの標準の割り当て**（タッチタイピングで一般に教えられるもの。左手 小指 Q A Z … 右手 人さし指 Y U H J N M など）。だれもがこう打つわけではない、と画面に書く。
- 割り当ては1つの表（キー → 指）で持つ。次のキーまでの時間が短く、同じ指が続くときなど、届かない・間に合わない所は `piano-hand` の「届かない所の選び直し」と同じ考えで直す（直した所はわかるように）。
- 段階C で「使う指を少なくした打ち方」（人さし指と中指中心など）を選べるようにして、くらべる。

## 打つ時間（「ながめる」のとき）
- 一定の間隔から始める（段階A）。
- 段階B で、キーの間の距離・同じ手か左右交互か・同じ指が続くか、で間隔を変える簡単なモデル。値は商用可の出どころで確かめられたものだけを使い、なければ「推定」と書く。

## 形
- 上に固定: キーボードと両手の3D（ななめ上から）。いま打った文字の行（ながめるでは文、再現では押したキーの並び。再現では文字を出さずキーの刻印だけでもよい。作りながら決める）。
- 下にスクロール: モードの切りかえ・速さ・配列・見せ方（皮ふ・半透明・骨・筋肉）・説明・おもな出どころ。
- 画面の「つぎへ」1つで: ①ホームポジションの手 ②1文字ずつ（どの指がどのキーへ） ③ふつうの速さで文 ④骨と筋肉を透かして ⑤自分で打ってみる。
- スマホ（幅 375px）で確かめる。

## 作り方（`piano-hand` からの流用）
- 体内ダイブの3本と同じく、**ある版を写して別に育てる**（`piano-hand` はまだ作り込みが続くので、共有にしない）。写した元: `piano-hand` の 2026-10-15 の commit `a25440d`（v050-thumbspring 以降）。写した元の版を DEVNOTES に書く。
- そのまま使う: `skeleton.js`・`skin.js`・`skinview.js`・`tissue.js`・`scene.js`、`hand.js` の FK・IK・手首の姿勢の部分、`check.js` の指どうしのぶつかりの検査、`tools/skin-check.js`。
- 作り直す:

| ピアノ | タイピング |
|---|---|
| `keys.js`（鍵盤は横1列） | `keys.js`: キーの格子。キーの間隔 19.05mm、段ごとのずれ、キーの上面の高さと傾き（段ごと）、押しこみ 約4mm。配列は JIS から（US は段階C） |
| `keyboard.js`（支点で回る鍵） | `keyboard.js`: まっすぐ沈むキーキャップと刻印 |
| `fingering.js`（動的計画法で運指） | `fingering.js`: キー → 指の表と、届かない所の選び直し |
| `songs.js`・`import.js`（楽譜） | `texts.js`: 「ながめる」の文。`input.js`: キー入力（時刻つき）・画面のキーボード |
| `hand.js` の手首の解き方 | 奥・手前の段への届き。手首を浮かせる／台に置く |
| `view.js`・`main.js` | 鍵盤・ノーツの代わりにキーボードと文字の行、2つのモード |

- `hand.js`（971行）は 800行をこえているので、写すときに「FK・IK」と「打つ計画・手首」に分ける（RULES 2章）。

## 段階A（はじめの版）
- `piano-hand` を写して、ピアノの部分を外す。`_dev/tools/new-app.ps1` で登録（保管庫）。
- キーボード（JIS）の寸法と見た目、標準の指の割り当て、手首の奥・手前への届き。
- 「ながめる」モード（一定の間隔）。
- シミュレーションだという一文・おもな出どころ・解析の1行・スマホ。
- 確かめ: 全部のキーに指先が届くか、指どうし・指とキーがめりこまないか（`check.js`）、`__poseSheet` で上の段・下の段・数字の段・左右の小指の端を見る。

## 段階B
- 「再現する」モード（押した・離した時刻のとおり。リアルタイムと再生）。画面のキーボード。
- 「ながめる」の打つ間隔のモデル。

## 段階C以降（案）
- 使う指を少なくした打ち方（くらべる）。US 配列。かな入力（ローマ字入力とくらべると、打つキーの数と指の動きがちがう）。
- 英語対応（入口へ移すとき）。

## やらないこと
- ゲームにしない（速さ・正確さの点数、目標、練習の課題を作らない。打鍵の速さは表示しても、ほめたり順位をつけたりしない）。8.3 の判定を公開前に。
- 商用不可のデータ（上の2つなど）を使わない。画面に「非営利」と書かない。
- 打った内容を保存・送信しない。本物のログイン画面などに似せない。
- 実在のキーボードの製品名・ロゴを出さない。
