# 体内ダイブ 開発メモ（引き継ぎ用）

> 3アプリ（体内ダイブ・尿の旅・血管の旅）の全体像と共通の注意点は `../DEVNOTES.md`。このファイルは本家の詳細。

最終更新: 2026-10-03 / 初期リリース 1.0（= v3c）

口・鼻・肛門から人体の管（消化管・気道）に入り、3Dで探検するアプリ。素材（食べ物・異物）を選ぶと、消化・吸収・排出までをシミュレーションする。亜種として「尿の旅」（`../urinary-dive/`）がある。

## 2. 座標系と単位

- 単位は **cm**。`x` = 体の左（患者の左）が +、`y` = 上が +、`z` = 前が +。
- 鼻孔 ≈ (0, 0.2, 10)、口 ≈ (0, -4.2, 10.2)、肛門 ≈ (0, -99, 0.5)。
- 管の太さはおおよそ実寸。長さは小腸・大腸を大きく短縮している。

## 4. 仕組みの要点

### 管の描画と合流部
- 管は中心線＋半径の「チューブ」。内側から見るので `DoubleSide` で、法線は視線側に反転させている。
- 合流部は、各管のシェーダに**相手の管のカプセル列**を渡し、その中に入った自分の壁を `discard` して穴をあける。カプセルは合流部付近だけ（`groups`、球で事前判定）。
- 合流部の近くはひだを消す（`jf`）。こうしないと穴の縁がずれて外の闇が見える。
- 閉じ具合が変わる関門や胃の膨縮を**合流部に置かない**こと。穴の大きさは静的なので、ずれて隙間が見える。

### 当たり判定
- 移動可能域 = 各線分の半径 `r*cf*scaleAt() - 0.1`（壁から 0.1cm の余裕）。
- **余裕（マージン）を増やすと合流部で通れなくなる**（v3b で口腔→咽頭が塞がった）。変更したら必ず 3 入口の通し確認をする。
- 関門が閉じていると半径が負になり線分ごと除外される。加えて `crossesClosed()` で「関門の s をまたいだ移動」を取り消す（細い関門をすり抜けないための二重化）。

### 移動モード
- `control='guide'`（順路モード）: `guide.s` を W/S で進め、カメラは順路上の点へ lerp。向きは進行方向を自動で向く（ドラッグ後 1.5 秒は手動）。
  - 既定の向き: 口・鼻から入ると「肛門へ／肺へ」、肛門から入ると「口へ」。G で 既定 → 反対 → 自由移動。
  - 目標 `guide.s` はカメラの投影位置から ±1.5cm 以内に制限（関門で止まっている間に先走らないため）。
- `autoOn`: 順路モードを自動で進める。
- 自由移動: 速度ベクトル＋減衰、サブステップで `constrain()`。
- 体外（`inBody=false`）では当たり判定なし。開口部の内側に近づくと `tryReenter()`。

### 生理シミュレーション（`simStep(dt分, zone)`）
- 体内時間は区分ごとの倍率 × 早送り（F で ×10）。
- 胃: 酸で変色・ほぐれ（`prog`）。幽門は `prog>=1`（かゆ状）か、空腹期の MMC 第3相でだけ開く。満腹時は胃内容が 3.2mL/分で減る。
- 小腸: 胆汁で黄色、栄養吸収、胆汁酸は回腸で再吸収。回盲弁は小腸滞在 150 分以上で開く。
- 大腸: 細菌増加・発酵（ガス）・水分吸収・ステルコビリンで茶色。**S状結腸で止まり**、大蠕動（`baseReady()` か食事の胃結腸反射）で直腸へ。直腸で便意 → 肛門が開く。
- ブリストル型は水分率から判定。
- アルコール: Widmark（60kg、分布容積 42L、分解 6.5g/時）。部位ごとに吸収速度と初回通過率（直腸は 0.97）。
- ボタン電池: 食道の第2狭窄部（`LODGE`）で詰まり、損傷 `burn` が約 2 時間で進む。
- ツキヨタケ: 胃に 40 分で嘔吐（逆流フロー）、小腸で吸収されると下痢。肛門から入れた場合はデータ不足のため毒性なし（画面にも明記）。
- カプセル内視鏡は、関門を W で押し続けると押し広げて通れる（逆走も可）。

### 三人称視点
- 表示はアバター（素材ごとの形・色・質感）。カメラは**管の中心線に沿って後ろ**に置く。
- 自分の真後ろに直接置くと、壁際で置き場所がなくなって本体に寄り、ちらつく（v3b で修正）。

## 5. 検証のしかた

- デバッグ用に `window.__bd` を公開している: `begin(mat, entry, belly)`, `setControl()`, `SIM`, `G`, `P`, `loc`, `camera`, `tpsCam`, `avatar`, `locate`, `guide`。
- フレーム内の例外は `window.__bdErr` に入る。
- 例: `__bd.begin('meat','mouth','hungry')` → `dispatchEvent(new KeyboardEvent('keydown',{code:'KeyW'}))` → 数秒待って `document.getElementById('locName').textContent` を見る。
- **Browser ペインが非表示だと requestAnimationFrame が止まり、何も進まない**（`document.hidden === true`）。ペインを表示するか、尿の旅のように `simRun(秒, キー)` のような手動ステップ関数を入れて検証する。
- ローカルの file:// は Browser ペインで開ける（作業フォルダ内）。更新後は再 navigate しないと古いスナップショットのことがある。

### 変更後の回帰チェック（毎回）
1. 口から: W 押しっぱなしで咽頭 → 食道 → 胃まで進む（一人称と三人称の両方）。
2. 鼻から: 気管まで進む。
3. 肛門から: 「口へ」で横行結腸まで進む。
4. コンソールエラーなし（`__bdErr` が空）。

## 6. 既知の課題・今後の案

- 管が細い・急に曲がる所では、三人称カメラが近づきすぎることがある。
- 三人称の見た目は、肉が口からS状結腸まで行く経路しか目視確認していない。
- 合流部の穴の縁に細い隙間が見えることがある（カプセル近似のため）。
- 尿道など別ルートは亜種「尿の旅」で実装済み。統合するかは未定。
- 亜種の案（ユーザーに提示済み）: 血管の旅、耳と涙の管、体の違い（子ども・高齢者・妊婦）、病気の体、動物版、検査・治療シミュレーター、薬の旅、ミクロ視点。

## 7. 亜種「尿の旅」（`../urinary-dive/`）の差分

- 同じエンジンを複製して、解剖と生理を差し替えたもの（共通化はしていない）。
- 管: 左右の腎臓（腎杯3つ→腎盂→尿管）、膀胱、尿道（男性 `uM` / 女性 `uF`。開始時に `setSex()` で片方だけ有効にする）。
- 男女の尿道は空間で重なるので、**互いの穴あけ処理はスキップ**している（`A.def.sex && B.def.sex`）。
- 膀胱は膀胱三角の点 `BASE` に向かってしぼむ（頂点シェーダで軸ごと縮める。当たり判定の線分も `shrinkPt()` で同じ変形）。膀胱三角と頸部は伸びない（重み 0）ので、尿管・尿道との合流部は静的。
- 尿管はふだんつぶれていて（`aUre`）、自分のいる位置 `uBolus` の周りだけ広がる。
- 結石は狭窄部（`NARROW`: 腎盂尿管移行部 5mm・交差部 4.5mm・尿管膀胱移行部 3.5mm）で詰まり、水腎症で腎盂がふくらむ（`HYD` → `uHydro`）。
- 細菌は括約筋に止められない（尿管口だけは 4 秒押してよじ登る）。C で壁にしがみつくと、排尿で流されない代わりに 9 割が減る。
- 検証用に `window.__ud.simRun(秒, ['KeyW'])` がある（ペインが非表示でも進む）。テスト後に実時間の時計が先に進むので、その直後の見た目は正しくないことがある。
- 出典（v001i、2026-10-07〜）: 開始画面の「このアプリについて・おもな出どころ」。確かめた資料と、目安にした数値の一覧は `../DEVNOTES.md` の 3.2。
- 公開: タイトル「尿の旅」（URL は `../PUBLISH.local.md`）、ランチャー: `../urinary-dive/launcher.html`

## 8. 亜種「血管の旅」（`../blood-dive/`）の差分

- 尿の旅のエンジンを複製。公開: タイトル「血管の旅」（URL は `../PUBLISH.local.md`）、ランチャー: `../blood-dive/launcher.html`
- 管: 静脈（大腿静脈・下大静脈・腎静脈・門脈・肝静脈・内頸静脈）、右心系 `rh`（上大静脈→右心房→三尖弁→右心室→肺動脈弁→肺動脈幹）、左右の肺動脈・肺静脈、左心系 `lh`（左心房→僧帽弁→左心室。心尖で行き止まり）、`aorta`（左心室の中から始まり、大動脈弁→弓→腹部→右脚の大腿動脈まで）、枝（総頸動脈・腎動脈・上腸間膜動脈）。
- **毛細血管は縮尺上入れない**ので、動脈の行き止まり（`portalOut`）に着くと `passCapillary()` で説明カードを出し、対応する静脈（`portalIn`）の始まりへ移す。順路では `portal` 印の点をまたいだときに同じ処理をする。逆向きには通れない。
- 心臓の周期 `SIM.phase`（0〜1、心拍数で進む）から `heartWave()` が心室・心房の縮み、動脈の拍動、弁の開閉（房室弁は拡張期、半月弁は収縮期に開く）を決める。心電図は `ecgAt()`。
- 拍動の重み（属性 `aVent`/`aAtr`/`aArt`）は合流部の近くで 0 にしている（`jf` を掛ける）。穴の位置がずれないため。
- 弁の見た目は関門の収縮で、閉じたときの尖の数を `uGateL` で渡す（三尖弁3・僧帽弁2）。
- 大動脈は左心室の中から始まるので、`crossesClosed()` で「左心室 ↔ 大動脈」の移動も大動脈弁で止めている。
- 順路は右心房から右心房へのループ（左右の肺 × 行き先4つ = 8本）。1周ごとに肺の左右を交互にし、行き先は「おまかせ」で順番か、N キーで指定。
- **順路の作り方の注意**: 次の管が前の管の途中から出ている場合、前の管を「次の管の始点に一番近い点」で切ること。行き止まりまで行ってから折り返すと、`guide.s` をカメラ付近に制限する処理と噛み合って止まる（肺動脈幹→右肺動脈で実際に起きた）。`buildRoute()` は自動でそうしている。
- 素材: 赤血球（酸素飽和度で色が変わる）、血栓（肺動脈に詰まり→肺塞栓症→血栓溶解薬）、カテーテル（大腿動脈から逆行、弁を押し広げる）。
- 検証用に `window.__vd.simRun(秒, ['KeyW'])`。
