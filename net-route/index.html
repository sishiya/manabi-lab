さわれるところ: 線をタップ＝ケーブルを切る・つなぐ／中継の点＝混ませる／動く四角＝中身を見る。

    • 名前の問い合わせ（DNS）
    • あいさつ（TCP）
    • 暗号（TLS）・ページをください
    • ページの中身
    • 受けとったよ（ACK）
    • 送り直したもの
    • 海底ケーブル　WiFi（電波）
    • 図の線の長さは本物と合っていません（線の数字が長さ）。四角が重ならないよう少しずらして描いています（※ 目印）。
    このアプリについて

    学習用に簡単にした計算のモデルです。ブラウザからは本物の経路を測れない（traceroute が打てない）ので、あなたの回線を測っているわけではありません。

    計算していること

    • 光ファイバーの中の光の速さ＝真空の光の速さ ÷ 屈折率 1.4675（光の包みが進む速さを決める値・1310nm）＝ 約20万km/秒（1km で約4.9マイクロ秒）。WiFi は空気中なので真空とほぼ同じ。
    • 線の長さ: 陸揚げ局などの緯度経度からいちばん短い道（大円距離）を出し、本物のケーブルは曲がっているので海は 1.1 倍・陸は 1.3 倍にした（推定）。家からプロバイダ・まちの中の長さは仮定。
    • 中継ごとに、送り出す時間（大きさ ÷ 回線の速さ）と処理の時間（0.02ミリ秒・推定）。WiFi は順番待ち（平均2ミリ秒・推定）。混ませた中継は平均30ミリ秒待ち、8%が捨てられる（推定・演出に近い）。
    • 流れ: 名前引き（DNS。プロバイダが答えを覚えている前提。返事が1秒来なければ聞き直す＝推定）→ TCP のあいさつ → TLS 1.3 のかぎ → ページをください → ページ（60KB を 1460 バイトずつ・42個）。
    • 送る数は最初10個、「受けとったよ」が1つ返るたびに1つ増やす（スロースタート）。返事が来ないと待って送り直し、送る数を1にもどす。待ち時間は最初1秒、往復を測ったら往復の3倍（下限0.2秒）で、時間切れのたびに2倍にのばす。

    簡単にしたところ

    • 道と陸揚げ局は例です（本物のケーブルの地図を写したものではありません）。
    • 本物の道は、会社どうしの約束（BGP）で決まり、いちばん早い道とは限りません。ここでは各中継が「いまいちばん早い道」を選び、ケーブルが切れるとすぐ組み直します。本物は組み直しに数十秒〜数分かかることもあります。
    • 「受けとったよ」は1つずつ返し、送り直しは時間切れのときだけにしました（本物はもっと工夫があります）。待ち時間の下限は、RFC の1秒ではなく Linux と同じ0.2秒にしました。
    • ページは HTML 1つ（60KB の例）だけ。本物のページは画像やスクリプトなど何十ものファイルを読みます。サーバーがページを作る時間・暗号の計算・光回線の上りの順番待ちなどは入れていないので、本物はもっとかかります。
    • 最近は、あいさつと暗号を1往復にまとめる HTTP/3（QUIC）や、2回目からの近道（つなぎっぱなし・TLS の再開）があり、いつも4〜5往復かかるわけではありません。ここは基本の形だけです。

    おもな出どころ

    • 光ファイバーの屈折率 1.4675（長い距離用のシングルモード光ファイバー・1310nm）: Chaudhry, Yanikomeroglu (2020) Free Space Optics for Next-Generation Satellite Networks（arXiv）。海底ケーブルでよく使う 1550nm でもほぼ同じ（ちがいは 0.1% より小さい）。
    • TCP: RFC 9293（あいさつ）、RFC 6928（最初に送る数 10）、RFC 5681（スロースタート）、RFC 6298（送り直しの待ち時間）
    • TLS 1.3: RFC 8446。DNS: RFC 1034・RFC 1035
    • 道の組み直しに時間がかかること: Labovitz, Ahuja, Bose, Jahanian (2000) Delayed Internet Routing Convergence（ACM SIGCOMM）
