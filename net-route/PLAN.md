# インターネットの経路 企画書

作成 2026-10-29

## ユーザーの依頼
2026-10-29「インターネットの経路アプリを試作して」（IDEAS 26）。中身の指定はまだない。

## ねらい
ページを1枚開くあいだに、データが小さな包み（パケット）に分かれ、家のルーター → プロバイダ → IX → 陸揚げ局 → 海底ケーブル → データセンター と中継されていくようすを、**時間をうんと遅くして**見る。
- 遅れのほとんどは「光がケーブルを進む時間」で、遠いサーバーほど何往復ぶんも待つこと（あいさつ・暗号のかぎ・少しずつ増える送り方）。
- 道は1本に決まっていない。ケーブルを切ると、次の中継から別の道を通る。なくなった包みは送り直す。
- 近くのサーバー（東京のデータセンター）を選ぶと、同じページが何倍も早く届く。

## 形
- 上に固定: 経路の図（Canvas 2D・紺地の線画）。点＝中継、線＝ケーブル、動く小さな四角＝パケット（種類で色）。いまの時刻（ミリ秒）。
- 下にスクロール: 「ページを開く」ボタン、サーバーの選択、時間の遅さ、いまの段階の説明（1〜2行）、かかった時間の内訳、このアプリについて。
- さわる: 線をタップ＝ケーブルを切る／つなぐ。中継をタップ＝混ませる。パケットをタップ＝中身（宛先・番号・通った中継の数）。
- スマホ縦では図を縦向き（上が自分、下がサーバー）にする。

## 段階A（この版・試作）
- 道のグラフ（11の点・12本の線）。長さは陸揚げ局などの緯度経度から大円距離を出し、海は×1.1・陸は×1.3（推定）。家の中・まちの中の長さは仮定。
- 光の速さ: ファイバーの中は c ÷ 1.4675（屈折率）＝ 約20万km/秒（1km で約4.9マイクロ秒）。WiFi は空気中なので c。
- 中継ごとに「送り出す時間（大きさ÷速さ）＋処理（推定）」、WiFi の順番待ち（推定）。
- 流れ: DNS（プロバイダの名前引き。覚えている前提）→ TCP の握手 → TLS 1.3 → GET → データ 60KB を 1460 バイトずつ。送る数は最初10（RFC 6928）から、ACK 1つで1つ増やす（スロースタート）。
- なくなったら待って送り直す（RTO。最初は1秒、往復を測ったら3倍・下限 0.2秒＝Linux 風、時間切れで2倍。タイマーは1つ、送り直しも cwnd の中で）。
- 道は各中継が「いまの地図でいちばん早い道」を選ぶ（ダイクストラ）。切るとすぐ組み直す（本物はもっとかかることがある＝画面に書く）。

## 段階B以降（案。話してから）
- 名前引きを根っこ（ルート → .com → 会社のサーバー）からたどる「覚えていない」モード。
- 地球儀の上の本物の位置（神の視点マップとつなぐ）。海底ケーブルの公開データは使える条件を確かめてから。
- WiFi の中（電波の見える部屋とつなぐ）・光ファイバーの中の光（全反射）へズーム。
- 動画・大きいファイルで、ケーブルの太さ（帯域）が効いてくるところ。

## やらないこと
- 本物の traceroute（ブラウザからは打てない）。見せるのは計算のモデルだと画面に書く。
- 実在の会社・ケーブル・サービスの名前。陸揚げ局は地名だけ、道は「例」と書く。
- 非営利だけのデータ（no-noncommercial-sources）。

## 簡単にするところ（画面にも書く）
- 道すじとケーブルは例。本物の経路は会社どうしの約束（BGP）で決まり、いちばん早い道とは限らない。
- 中継の処理・WiFi の待ち・混んだときの待ちとなくなる割合は推定（演出に近い）。
- ACK は1つずつ（SACK に近い形）、送り直しは時間切れだけ（速い再送はなし）。

## 出どころ（確かめたもの）
- 光ファイバーの屈折率 1.4675（1310nm、Corning のシングルモード）→ 約4.9µs/km。arXiv 2010.03098 の本文で確かめた（2026-10-29）。
- TCP: RFC 9293（握手）、RFC 6928（最初に送る数 10）、RFC 5681（スロースタート）、RFC 6298（送り直しの待ち時間、最初 1秒）。
- TLS 1.3: RFC 8446（1往復でかぎを決める）。DNS: RFC 1034・1035。
- 道の組み直しに時間がかかること: Labovitz ら 2000「Delayed Internet Routing Convergence」（SIGCOMM）。

## 比べたもの（RULES 6章）
- ns-3（C++・GPL）: 本格的だが GPL でブラウザ向けでもない → 使わない。
- YJDoc2/Network-Simulator（Svelte・MIT/Apache）: 汎用のパケット図。考え方（点と線・パケットの移動）だけ参考。
- npm の netsim: 線ごとの遅れと損失のモデル。同じ考え方を、光の速さと長さから遅れを出す形で自分で書く（小さな出来事の列のシミュレーション。コードは写していない）。
