# いのちの系統樹 企画書

作成 2026-10-15

## ユーザーの依頼
生きものの進化の歴史を樹形図で見られるアプリ。理想は、いままで分かっている全部の生きものを網羅し、クリックで詳細、検索でき、種や目がひと目で分かる。情報量と、ネットの情報を集めてアプリにしてよいかも調べて、問題のない範囲でまず初期版を。

## 調べたこと（2026-10-15）

### 情報量
- 名前のついている生きもの（今いる種）は **約 220万種**（Catalogue of Life 2025 年版の発表。2026-09-11 版 COL26.9 の中身は名前が約 543万件＝同じ種の別名もふくむ）。COL 自身は「知られている種の 8 割ちょっと」をおさめていると書いている。
  - 2026-09 版の数（COL の API の `count`）: 真核生物 2,224,564 種・細菌 26,525・古細菌 792（ウイルス 17,552 は生きものの系統樹に入れない）。
- 進化の枝分かれ（系統）の図としては **Open Tree of Life** の合成の系統樹が最大で、先端が **約 239万**（2025-12-20 版。研究 1,931 件・系統樹 2,064 本をまとめたもの）。分かっていない所は「くし形」（いっぺんに枝分かれ）になっている。
- 全部をアプリに入れると: 1種あたり学名と ID だけで 50〜80 バイト → 名前だけで 100MB 以上（圧縮しても数十MB）。和名・説明を足すともっと。GitHub Pages に置けなくはないが、リポジトリが重くなり、毎月の更新にも追いつけない。
- → **上のほう（界〜綱、約千のまとまり）だけをアプリに入れ、その下（目・科・属・種）は開いたときに COL の公開 API から読む**。これで 220万種すべてにたどり着ける。

### 使ってよいか（利用条件）
| データ | 条件 | 使い方 |
|---|---|---|
| Catalogue of Life（COL） | **CC BY 4.0**（2023-08〜）。名前を出せば商用もよい | 分類・学名・種の数。API（キー不要・CORS あり）で読む。画面に出典と引用のしかたを書く |
| Open Tree of Life（合成系統樹・分類） | 「前からの条件がない限り **CC0**（著作権の放棄）」 | 上のほうの枝分かれの形。作るときだけ API で読み、アプリに入れる |
| Wikidata | **CC0** | 和名（ラベル）・短い説明・Wikipedia への行き先 |
| Wikipedia の本文 | CC BY-SA（同じ条件で配る義務）→ アプリの中身（CC BY-NC）とまぜられない | **本文は写さず、リンクだけ** |
| 写真（Wikimedia Commons など） | 1枚ずつ条件がちがう（BY-SA・NC もある） | 初期版では使わない（段階Bで1枚ずつ条件を出せる形を考える） |
| TimeTree（分かれた年代） | 条件を確かめられていない | 初期版では使わない |

- 事実（学名・分類・数）そのものには著作権がないが、データベースとしての権利と、各データの条件にしたがう。上の3つはどれもしし屋の公開（収益化の可能性あり）と両立する（非営利だけのものは使わない）。
- 気をつけること: COL の API はみんなのもの。開いたときだけ読み、同じものは2度読まない（アプリの中でおぼえる）。検索の文字は COL・Wikidata へ送られる（画面に書く）。

## ねらい
- 「ヒトとキノコはどこで分かれた？」「カメはどの仲間？」を、枝をたどって自分で見つける。
- 界・門・綱・目・科・属・種の階級を色でひと目で。まとまりの大きさ（種の数）も数字で。

## 形
- 画面の上（スマホ）／左（パソコン）に樹形図。左が根もと、右へ枝分かれ。ドラッグで動かし、ホイール・ピンチで拡大。
- 名前をクリック → 下（右）に詳細、閉じていれば次の枝を開く。もう一度で閉じる。
- 検索: 和名（Wikidata）か学名（COL）→ 選ぶとその種まで枝を開いて、真ん中に。
- 枝分かれの形: 上のほうは Open Tree の系統樹（進化の順）。名前のないふしは小さな点（「この先で分かれた」）。綱より下は COL の分類（目→科→属→種）。

## 段階A（この版）
1. 作るときの道具 `tools/build-backbone.mjs`: COL の界〜綱 → Open Tree で同じ名前を探す → その枝分かれの形を取る → Wikidata で和名 → `data/backbone.js`。
2. 樹形図（Canvas）・開く／閉じる・パンと拡大・色の凡例。
3. 綱より下を COL から読む（多いときは「あと N 件」）。和名は Wikidata からまとめて。
4. 詳細の欄（和名・学名・階級・種の数・分類の道すじ・説明・外へのリンク）。
5. 検索（和名・学名）→ その場所まで開く。
6. このアプリについて・おもな出どころ・データの条件。

## 段階B以降（案）
- 分かれた年代の目盛り（条件を確かめた年代のデータか、確かめた論文の値だけ）。
- 写真（1枚ずつ作者と条件を出せるもの）。
- 綱より下も Open Tree の枝分かれの形にする（開くたびに API で）。
- 絶滅した生きもの（恐竜など）の扱い。英語。

## やらないこと
- 全種をアプリに入れること（重い・古くなる）。
- Wikipedia の本文を写すこと。条件の分からない写真。
- ウイルス（生きものの系統樹にはふつう入れない。Open Tree にもない）。

## 簡単にするところ（画面にも書く）
- 上のほうの形は Open Tree の合成系統樹を、COL の界〜綱の名前で切り出したもの。Open Tree で見つからないまとまりは COL の親の下につなぐ。
- 綱より下は分類（COL）で、進化の枝分かれの順そのものではない。
- 和名は Wikidata のラベル。同じ学名が動物と植物にあるときなどは、ちがう和名が出ることがある。
