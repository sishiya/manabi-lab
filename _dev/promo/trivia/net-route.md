# うんちく台本: net-route（インターネットの経路）

2026-11-02 作成（台本だけ）。仕様は `PATTERNS.md`。
アプリで作れる絵: 地球儀の上の海底ケーブルとパケット、光の速さと長さからの遅れ、ケーブルを切ると道がかわる、伝書鳩・衛星、スマホの仮のページが順番に描かれる。

---

### net-route-1  型H  「シカゴ→ニューヨーク、速いのはどっち？」　◎おすすめ
- 題名: 【うんちく】光ファイバーより速い通信がある。株の取引の世界では… ／ EN: Did you know? Traders beat fiber optics with old-fashioned radio towers
- 尺: 35秒　しゃべり: (2) VOICEVOX か (1)　へぇ度: ★5
- フック（0〜1.5秒の画面）: 「どっちが速い？」左＝光ファイバー（光）、右＝電波の鉄塔
- 台本:

  | 秒 | 画面 | しゃべり／字幕 |
  |---|---|---|
  | 0–3 | 2択「A 光ファイバー／B 電波の鉄塔」。地図にシカゴとニュージャージー | シカゴからニューヨークへ、株の値段を送る。速いのはどっち？ |
  | 3–5 | カウントダウン 2・1 | （考える間） |
  | 5–10 | 「B 電波」 | 答えは、電波の鉄塔 |
  | 10–17 | ガラスの中を進む光（遅め）と空気の中の電波（速め）の並走アニメ | 光ファイバーの中の光は、ガラスの中なので真空より約3割おそい。電波は空気の中をほぼ光の速さで進む |
  | 17–25 | 数字の帯: 光の限界 3.93ms／まっすぐに掘りなおした光ファイバー 6.65ms／電波の鉄塔 4.2〜5.2ms（推定） | わざわざ地面を掘ってまっすぐなケーブルを通した。でも、電波の鉄塔のほうが、さらに約2ミリ秒速かった |
  | 25–31 | 「2ミリ秒 = まばたきの約100分の1」→「合わせて 5億ドル以上」 | その2ミリ秒のために、全部で5億ドル以上 |
  | 31–35 | アプリの録画: 海底ケーブルをパケットが走る | ネットの速さを決めるのは、光の速さと、道の長さ |

- いちばんの「へぇ」の数字と、ふだんのものとのくらべ: 片道 6.65ms（光ファイバー）→ 4.2〜5.2ms（電波）。約2ms を縮めるのに合わせて5億ドル以上。2ms はまばたき（0.1〜0.15秒くらい）のおよそ100分の1。
- 絵の作り方: Canvas（地図の2点と直線・ケーブルの道、2本の並走アニメ、ms の帯）／アプリの録画（地球儀でケーブルを光の包みが進む場面）
- 出どころ:
  - G. Laughlin, A. Aguirre, J. Grundfest (2014)「Information Transmission between Financial Markets in Chicago and New York」Financial Review 49:283–312, arXiv:1302.5966, https://ar5iv.arxiv.org/html/1302.5966 （WebFetch 済み: 距離 1,179km、光の限界 3.93ms、以前の光ファイバー 7.25〜7.95ms、2010年8月からの低遅延の光ファイバー 6.65ms（のちに 6.55ms）、電波の網の推定 4.2〜5.2ms、設備と5年の運用で 5億ドル超）
- 推定・注意:
  - 電波の 4.2〜5.2ms は論文の**推定**。画面に「推定」。
  - 5億ドルは光ファイバーと電波の網を**合わせた**設備と5年の運用の見積もり（1本のケーブルの値段ではない）。
  - 「約3割おそい」はガラスの屈折率 約1.47 の目安（光ファイバーの一般的な値）。
  - 光ファイバーの会社名（Spread Networks）は画面に出さなくてよい（論文も本文で名前を出していない書き方）。
  - 「まばたき」は 0.1〜0.15 秒の目安。
- 計算（途中の値）: 6.65 − 4.7（電波の推定の中ほど）≈ 2.0ms。まっすぐなガラスの中の最短 = 3.93ms × 1.47 ≈ 5.78ms（本当のケーブルは道が曲がるので 6.65ms）。
- コメント欄の問い（任意）: 「2ミリ秒で、あなたなら何をする？」

### net-route-2  型A  「海底ケーブルを切るのはサメ…じゃない」
- 題名: 【うんちく】海底ケーブルをかじるサメ、じつは8年間ゼロ件 ／ EN: Did you know? Sharks caused zero cable faults in 8 years
- 尺: 30秒　しゃべり: (1)　へぇ度: ★4
- フック（0〜1.5秒の画面）: サメのシルエット（自分で描いた単純な線画）＋ケーブル、上に「犯人？」に ✕
- 台本:

  | 秒 | 画面 | しゃべり／字幕 |
  |---|---|---|
  | 0–3 | 「海底ケーブルの敵＝サメ」✕ | インターネットの海底ケーブル。切るのはサメ…じゃない |
  | 3–10 | 「2007〜2014年 サメ・魚にかまれた故障 0件」 | 2007年から2014年、魚やサメにかまれた故障は、0件 |
  | 10–15 | 「1959〜2006年でも 0.5%」 | その前の50年でも、全体の 0.5% |
  | 15–23 | 円グラフ: 船のいかり・漁の網 65〜75% | 本当の犯人は、船のいかりと、漁の網。故障の3分の2から4分の3 |
  | 23–30 | アプリの録画: ケーブルを切る → 次の中継から道がかわり、パケットが遠回り | 切れても、包みは別の道をさがして、遠回りで届く |

- いちばんの「へぇ」の数字と、ふだんのものとのくらべ: 魚・サメの故障 8年間で0件（それより前も 0.5%）。いかりと漁が 65〜75%。
- 絵の作り方: Canvas（線画のサメ・数字・円グラフ）／アプリの録画（ケーブルを切る「本当にあった切断」の場面）
- 出どころ:
  - International Cable Protection Committee（ICPC）の分析を伝える記事: Fibre Systems「Sharks don't dine on subsea fibre-optic cables, says ICPC」https://www.fibre-systems.com/news/sharks-dont-dine-subsea-fibre-optic-cables-says-icpc （WebFetch 済み: 1959〜2006 は魚にかまれた故障が全体の 0.5%、2007〜2014 はサメによる故障なし、いかりと漁が 65〜75%）
  - S. Hardy, Lightwave（2015-07-06）「Shark threat to submarine networks a bunch of jawing, says ICPC」https://www.lightwaveonline.com/network-design/high-speed-networks/article/16651582/shark-threat-to-submarine-networks-a-bunch-of-jawing-says-icpc （WebFetch 済み: 同じ数字、約11本のケーブルが修理）
- 推定・注意:
  - ICPC の元の報告（PDF）は文字が読めず、業界紙の2本で確かめた。画面の出どころは「ICPC（業界紙の報道による）」。
  - いかりと漁の割合は資料・年で幅がある（ITU は 8割以上とも）。画面は「3分の2〜4分の3（ICPC）」。
  - サメの絵は写真・他人の映像を使わず線画で。こわがらせない。
- コメント欄の問い（任意）: 「サメの話、信じてた？」

### net-route-3  型F  「ハトでインターネット、本当にやった」
- 題名: 【うんちく】ハトでインターネット。本当にやったら ping 53分 ／ EN: Did you know? Someone really sent internet packets by pigeon
- 尺: 40秒　しゃべり: (2) VOICEVOX 2人（聞き手・答える人）　へぇ度: ★4
- フック（0〜1.5秒の画面）: 「ping 53分」の大きな文字と、紙を足につけたハトの線画
- 台本:

  | 秒 | 画面 | しゃべり／字幕 |
  |---|---|---|
  | 0–3 | 「ping 53分」 | 聞き手「ping が 53分？ 壊れてるでしょ」 |
  | 3–8 | 「RFC 1149（1990年4月1日）」 | 答える人「ハトで送ったのよ。もともとはエイプリルフールの決まりごと」 |
  | 8–14 | 「2001年4月28日 ノルウェー・ベルゲン」 | 聞「…本当にやったの？」答「ベルゲンの Linux の集まりが、本当に」 |
  | 14–20 | 紙に印刷したパケット → ハトの足 → 飛ぶ → 読み取り | 答「包みを紙に印刷して、ハトの足に。着いたら読み取って、返事もハトで」 |
  | 20–27 | 結果の表示: 9個送って、4個返事、55%なくなる、往復 53〜106分 | 聞「結果は？」答「9個送って、返ってきたのは4個。往復 53分から106分」 |
  | 27–34 | 返ってきた順番: 0番・4番・2番・1番 | 答「しかも返事の順番はバラバラ。0番、4番、2番、1番」聞「ネットの包みって、順番ばらばらでも大丈夫なの？」 |
  | 34–40 | アプリの録画: 仮のページが「n番の包みを待っている」で止まる → 抜けがそろうと描ける | 答「ふだんのネットも同じ。番号で並べなおして、そろってからページが描ける」 |

- いちばんの「へぇ」の数字と、ふだんのものとのくらべ: 往復の時間 最短 3,212 秒（約53分）〜最長 6,389 秒（約106分）。ふつうの ping は数〜数十ミリ秒なので、約10万倍以上。
- 絵の作り方: Canvas（ハトと紙の線画、ping の文字の打ち出し、届く順番の札）／アプリの録画（伝書鳩の道・仮のページで抜けを待つ場面）
- 出どころ:
  - Bergen Linux User Group「The informal report from the RFC 1149 event」https://blug.linux.no/rfc1149/writeup/ （WebFetch 済み: 2001-04-28、返事 4つ、往復 3,211〜6,389 秒）
  - 同「ping のログ」https://www.blug.linux.no/rfc1149/pinglogg.txt （WebFetch 済み: 「9 packets transmitted, 4 packets received, 55% packet loss」、min/avg/max = 3211900.8/5222806.6/6388671.9 ms、icmp_seq の順 0・4・2・1）
  - D. Waitzman, RFC 1149「A Standard for the Transmission of IP Datagrams on Avian Carriers」1990-04-01（エイプリルフールの RFC）
- 推定・注意:
  - なくなった理由は「ハトのかごを閉め忘れた・ハトが包みなしで逃げた」などと報告にある（ハトが落ちたのではない）。かわいそうな話にしない。
  - 飛んだ距離は報告に書いていないので言わない。
  - ふつうの ping の「数〜数十ミリ秒」は目安。
- 計算（途中の値）: 3,211,900.8 ms = 3,211.9 秒 = 53.5 分。6,388,671.9 ms = 106.5 分。平均 5,222.8 秒 = 87 分。53分 ÷ 30ms ≈ 10.7万倍。
- コメント欄の問い（任意）: 「ハトとうちの回線、どっちが速い日ある？」
