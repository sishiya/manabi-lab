# リアルな描写のノウハウ（両ラボ共通）

3D や絵を「本物っぽく」見せたいときに読むメモ。コードを写すためではなく、**考え方と手順を参考にする**ためのもの。
新しい手本を見つけたら「手本」の章に足し、効いたコツは「原則」「チェックリスト」に足す。

- 2026-11-17 作成。最初の手本は、なちゃっとさんの「イカの水槽」（下の手本1）。

---

## 原則（まずこれ）

1. **質感は描かずに、本物から取る。** 手で作った模様やノイズは、すぐ作りものに見える。写真・実測の輪郭・スキャン（CC0 など出どころがはっきりしたもの）を使い、計算はそれを「貼る・動かす」ことに使う。
2. **形は本物の輪郭から測る。** 写真（背・横・腹など）から、体の長さに沿った幅・厚みの表を作り、それで立体を組む。「それっぽい楕円」で作らない。
3. **動きは「生きもののクセ」を何層も重ねる。** 1つの大きな動きより、小さな動きをたくさん重ねるほうが効く。呼吸、ひれの波、曲がるときのしなりの遅れ、傾き、目の動き、気まぐれな状態の切りかえなど。
4. **見る人は「カメラで撮った映像」をリアルだと感じる。** 媒体（水・空気）の色の吸収、光の筋、浮遊物、ピントのぼけ、動きのブレ、カメラワークを足すと、急に本物に見える。いわば撮影の欠点の再現。
5. **乱数でそろわなさを出す。** 個体ごとに、大きさ・状態に入る時間・位相・色の変わる間隔を変える。全員が同じ周期で動くと一瞬で作りものに見える。
6. **見えない所は省く。** 遠い個体・ぼけた個体の細部を描かないと、軽くなったぶんを見える所の質に回せる。

> ラボのルールとの関係: 4 の「撮影の欠点」は見せ方の演出なので、物理（RULES の「物理を曲げない」）とは分けて考える。シミュレーションの値は曲げずに、描き方だけで本物らしくする。画面には、計算したもの・演出・推定を区別して書く。

## 技法の一覧（どこに効くか）

| 効くところ | 技法 | メモ |
|---|---|---|
| 形 | 写真の輪郭 → 断面の表（幅・上の厚み・下の厚み）→ 立体 | 3方向の写真があれば十分。部位（胴・頭・ひれ）ごとに表を分ける |
| 模様 | 同じ写真を3方向から投影して貼る（向きで混ぜる） | UV 展開が要らない。背景色をそろえた写真だと切り抜きが楽 |
| 岩・地面 | 手続き的な形 → 5方向（上前後左右）の正射影で描く → 絵（写真・画像 AI）で塗る → 同じ方向から貼り戻す＋法線・高さの画像 | 画像 AI を使うなら出どころの書き方を先に決める（下の注意） |
| 砂・地面 | 色＋法線のテクスチャ、地面の高さを数 cm の幅でならして、ゆるい起伏 | |
| 生きものの動き | 状態の切りかえ（浮かぶ・ゆっくり泳ぐ・後ずさり・急発進）＋各状態に何秒いるかは乱数 | 驚かすと近くの個体だけ反応、など局所的な反応 |
| しなり | 首振り・上下の速さを入れた「ばね＋ダンパー」で体や腕を遅らせる | 遅れがあるだけで重さと柔らかさが出る |
| 傾き | 曲がるときに内側へ傾ける（傾き ∝ −首振りの速さ） | |
| 周期の動き | 呼吸（胴が少しふくらむ）、ひれの波（速さで振れ幅、後退で波の向きが逆） | |
| 色 | 色素胞の点を2段の細かさで重ね、数秒〜十数秒おきに濃く／淡く変える | 生きものは色が止まっていない |
| 水・空気 | 距離で色を吸う（赤がいちばん早く消える）＋青い散乱光 | 遠いものほど沈む。奥行きがいちばん伝わる |
| 光 | スポットライトの円すいの光の筋、底のゆらめく模様（細かさ違いの2枚を重ねる） | |
| 浮遊物 | 細かい粒。光の円すいに入ったときだけ光らせる | |
| 影・反射 | やわらかい影（ぼかし大きめ）、環境マップで反射 | 影は動かないなら毎フレーム作り直さない |
| カメラ | 被写界深度、ときどきピントを別の物へ移す、動きのブレ、ブルーム | |
| カメラワーク | 全体 → 寄り → 群れ → 下から見上げる → 横パン → 水面…と自動でカットを割り、なめらかに追う。わずかなぶれ | 撮影者がいるように見える |
| 軽さ | 画面での大きさ・ぼけの量で細かさを落とす。画面外は描かない | |

## チェックリスト（リアルにしたいとき、上から）

- [ ] 質感の元は本物か（写真・スキャン・実測）。出どころとライセンスを確かめた（商用不可は使わない）
- [ ] 形は本物の輪郭から測ったか
- [ ] 動きに小さなクセが3層以上あるか（呼吸・遅れ・傾き・目・色…）
- [ ] 個体ごとに乱数でずらしたか
- [ ] 媒体（水・空気・霧）で遠くが沈むか
- [ ] 光の筋・浮遊物・ゆらぎがあるか（その場に合うものだけ）
- [ ] カメラのぼけ・ブレ・カメラワークは合っているか（やりすぎると逆に作りもの）
- [ ] 遠く・ぼけ・画面外の手抜きで軽くしたか
- [ ] スマホ（393×852）でも重すぎないか。画面を離れたら止まるか（`assets/power.js`）
- [ ] 計算・演出・推定を画面で区別したか

## 注意

- **画像 AI の絵を素材にするとき**: 「出どころを画面に」のルール（RULES 9章）に合わせ、AI で作った素材だと書く。本物の標本・写真と誤解させない。使う前にユーザーに相談する。
- **他人の作品**: 「勝手に使ってよい」と言われていても、写すのは考え方まで。素材を使うなら、許可の投稿の URL と日付を出どころの記録に残す（ライセンスの文書がない場合は特に）。
- **抽象的な見た目が基本**: ラボの多くは紺色の線画（好みのメモ「Abstract house style」）。リアルにするのは、リアルさがテーマのアプリ（水槽・眺める系・自動収益化の映像など）だけ。

## 手本

### 手本1: イカの水槽（2026-11-17 調べ）
- ページ: https://cda-social.github.io/fish/aquarium （作者の X 投稿: https://x.com/nachat_dayo/status/2122238415194501138 、2026-11-16。作者は「ノウハウやモデルは自由に使ってよい、石・砂・イカのモデルは著作権フリー」と書いている。リポジトリにライセンスの文書は見当たらない）
- 作り: three.js（Vite でまとめた 1 ページ）。素材は webp/avif。
- 見どころ:
  - イカ = 背・横・腹の写真3枚（1672×941、背景は灰色でそろえてある）＋ JSON の断面の表（胴・ひれ・頭それぞれ64点ほど）。輪郭から立体を作り、写真を3方向から投影している。上に手続き的な色素胞の点と色の変化を重ねる。
  - 岩 = 1つにつき5方向 ×（色・法線・高さ）の15枚。コードに英語の画像生成プロンプト（「日本の水族館の玄武岩、細かい穴、上面に薄いほこり」）と、岩を5方向から 16:9 の正射影で描く関数が残っている。→ 手続き的な形を5方向から描き、画像 AI で塗って貼り戻した、と推定。
  - 水 = 色の吸収（赤 0.6・緑 0.26・青 0.1 の割合で距離に応じて減る）＋散乱光、光の筋、底のゆらめく模様、光の中だけ光る粒。
  - カメラ = 被写界深度・ピント送り・動きのブレ・ブルーム、6種類のショットを自動でつなぐ。
  - 動き = 4つの状態（浮かぶ・泳ぐ・後退・ジェット）、ばね＋ダンパーのしなり、曲がるときの傾き、呼吸 0.8Hz、ひれの波（速さで振れ幅、後退で逆向き）、体色が茶色く／白っぽくなる。
- ラボで生かせそうな所: `tank-window/`（水の吸収・浮遊物）、実物ベースの生きもの（写真3枚 → 断面の表 → 立体）、自動収益化の眺める映像（カメラワーク）。
