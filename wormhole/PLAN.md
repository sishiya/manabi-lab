# ワームホールを通りぬける 企画書

作成 2026-11-08

## ユーザーの依頼
「ワームホールのシミュレーションアプリを作って」。確かめた結果: **見どころは通りぬける見え方**、**動かし方は位置スライダー1本**（2026-11-08）。

## ねらい
ワームホールは、遠くの宇宙の別の場所へつながるかもしれない、**仮想の**トンネル。その「穴」は黒くなく、奥に別の宇宙の景色が見える。のどへ近づいて通りぬけ、振り返ると今度は元の宇宙が穴の中に見える。これを、光の道すじを本当に計算して描き、**画面の好きな点の光がどこから来たか**を自分で確かめる。

## 見る人の手がすること
- **位置スライダー1本**（こちらの宇宙 → のど → 向こうの宇宙）を自分で動かす。これが時間軸の代わり。「▶ 通りぬける」は同じスライダーを自動で動かすだけ。
- ドラッグ（2本指も）で見回す。「うしろを見る」で向きを反転。
- 景色の点をクリック／タップ → ろうと図（ワームホールを曲がった面で表した図）に、その光の道すじが出る。「向こうの宇宙から来た光」「のどを何回まわった」などを文で。
- 形のプリセット3つ（映画と同じ・長いトンネル・なめらかな口）。くわしくは長さ・なめらかさのスライダー（たたんでおく）。
- 空: 星空／方眼（2つの宇宙を色分け。ゆがみが見やすい）。

## 時間の見せ方
時間のスライダーは置かない。位置スライダーが旅の進み。カメラは各位置に止まって見ている観測者。

## 物理（確かめた式。James, von Tunzelmann, Franklin, Thorne 2015）
- 計量: ds² = −dt² + dℓ² + r(ℓ)²(dθ² + sin²θ dφ²)（式1）。重力 Φ は無視（論文も光については無視。式8の下）。
- Dneg の形（式5）: |ℓ| ≤ a で r = ρ、|ℓ| > a で r = ρ + M[x arctan x − ½ ln(1 + x²)]、x = 2(|ℓ| − a)/(πM)。レンズの幅 W = 1.42953 M（式7）。
- 光（付録A 式16）: dℓ/dt = p、dφ/dt = b/r²、dp/dt = b² r′/r³。球対称なので光は1枚の平面の中を進み、b（衝突径数）だけで道が決まる。カメラの向きとの関係: b = r sinψ（ψ は +ℓ の向きからの角度）。
- 映画の値: 2a = 0.01ρ、W = 0.05ρ（V章）。図7の他の長さ: 2a = ρ、10ρ。図9: 2a = ρ、W = 0.43ρ。カメラの基準位置 ℓ = 6.25ρ + a（図7）。のど半径 ρ = 1 km は論文の目安の値。
- のど（|ℓ| < a の円筒）の中は r = ρ で式が厳密に解けるので、数値で進めず一気に進める。

## 描き方（比較と選んだ理由）
| 手法 | しくみ | 正確さ | 速さ | ライセンス |
|---|---|---|---|---|
| sirxemic/wormhole | 角度ごとの1次元表を GPU で作り、画素は表を引く | 測地線（積分は後退オイラー） | とても速い | MIT |
| oseiskar/black-hole | 画素ごとに GLSL で積分 | 測地線 | 重い | MIT（銀河の画像は NC。使わない） |
| T-Lind/wormhole | 屈折の球で近似 | 測地線ではない | 速い | 表示なし（使わない） |

**選ぶ: 1次元表を CPU で RK4 で作り、32F テクスチャで GPU へ渡す**（sirxemic の考え方。コードは写さず自分で書く）。理由: 球対称なのでカメラ位置ごとに b だけの表で厳密。float へ描く拡張がいらずスマホで動く。同じ CPU の式をクリックの道すじと検証に使える。臨界 b = ρ の近くで角度が対数で発散するので、表の刻みは ln|1 − b/ρ| にする（線形補間でほぼ厳密）。

**確かめ**（`tools/verify.js`）: Ellis の場合の厳密解（自分で導いた Δφ = 2k K(k)、k = b/ρ、反射は 2K(ρ/b)）と数値積分を比べる。保存量 p² + b²/r² = 1 のずれ。表と直接積分の差。

## 批判役の指摘と決めたこと（2026-11-08）
- のどの近くで穴のふちが画面の外に出て、前を向いたままでは通過が見えない → **直した**: 下に「ぐるり一周」の帯を常に出す。「うしろを見る」と見回しのボタンも。
- 円筒のある形では b < ρ の側が対数でなく 1/δ で発散する → **そのまま**: 表の誤差は全体の角度の 2×10⁻³ 以下で、その角度の差は 1 画素の中に入る（`tools/verify.js`）。
- 同じ b に2本の光がある・漸近の補正・float の線形フィルタ → 最初から ψ で分けた表、asin の補正、texelFetch で手補間にしてある。
- Ellis では継ぎ目を試せない → **足した**: 歩幅 1/10 との比較と、全天を足し合わせた割合の比較。
- スライダーの区間 → **直した**: のどの円筒に区間を割り当て、長い形では入口・出口の目盛りを出す。
- スマホ → **直した**: 縦長ではろうと図を景色に重ねる。見回しはボタンでも。タップは移動量で区別。
- 文 → **直した**: 「重力は無視」を「時間の進みの差と潮汐力は入れない」に。プリセットは「細いのど」。作品名は出どころの1か所だけ。
- ろうと図の高さは模式（本当の r(ℓ)・φ を使い、高さだけ `fnHeight` で作る）。「回った」は のどの中心から見た角度 Φ を 360° で割った整数。

## 段階A（この版）
位置スライダー、見回し、光の表、2つの宇宙、ろうと図、クリックで道すじ、形のプリセット、空の切りかえ、読み取り（のどまでの距離・穴の見かけの大きさ・向こうの宇宙が空の何%か）、解説と出どころ。保管庫に置く。

## 段階B以降（案）
- 穴を支えるのに要る負のエネルギーを場所ごとに（アインシュタイン方程式から）。
- 動いているカメラの光行差。2つの宇宙の天体に距離を持たせる（視差）。
- 英語対応（入口へ移すとき）。

## やらないこと
- 自由飛行（選ばなかった）。重力・潮汐力。回転するワームホール。作れるかどうかの断定。

## 簡単にするところ（画面にも書く）
- ワームホールは見つかっていない仮想のもの。開いたままにするには負のエネルギーを持つ特殊な物質が必要で、大きなものは保てない可能性が高い（論文は「おそらく、ただし確かではない」）。
- 時間の進みの差と潮汐力は入れない（光の道すじへの影響は論文でも無視）。カメラは止まっている（光行差なし）。空は無限に遠い絵（視差なし）。
- 星空・目印の惑星は作りもの（演出）。「向こうの宇宙」も説明のための呼び名で、同じ宇宙の遠い場所でもよい。
