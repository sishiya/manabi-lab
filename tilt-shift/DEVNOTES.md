## しくみ
- ぼけ・計算は以前と同じ（帯: 線からの距離で RAMP=0.35 かけて R まで。奥行き: r = kf·|1/z0 − 1/z|。Held の式 b = A·|1/z0 − 1/z| を 64×40 の点に当てはめて s）。距離の格子はカメラが止まって 150 ms たってから読む（動かしているあいだは前の結果）。遠い点（max(2500, 近さ×3.5) m より先）は使わない。
- 「ポリゴンに見えるわけ」と、その手当て（PLAN 段階E に7つ）: 敷地を細長く分ける・壁は式で（窓に空を映す・雨だれ・下ほど暗い・1階の店）・屋上の防水の色と汚れ・地面の色むら・空気のかすみ・樹冠のつぶ（Worley）・小物（人・電柱・室外機）。
- 色: 光の量（リニア）で描き、blur.js でぼかしてから露出 `S.exp`（0.62）・ACES の近似・ガンマ。instance の色は `convertSRGBToLinear`（Kit.lin）。
- InstancedMesh は範囲が元の形（原点の小さな箱）で決まるので、`frustumCulled = false`（忘れると原点が画面の外で全部消える）。
- 田んぼの村: 谷の床は1枚の板に canvas の種類の絵（R=種類・G=田ごとのちがい・B=穴）を Nearest で貼り、式で描く。川と土手は別の帯の形、板は B で穴をあける。

## ハマったところ
- ぼけを集めるとき「その点のぼけが中心まで届く点だけ足す」と絵が外へずれて拡大して見えた → 帯は同じ重み、奥行きは前の点だけ外す。
- onBeforeCompile の文が同じ材質は three.js が同じシェーダーを使い回す → `customProgramCacheKey` を材質ごとに（Kit.mat は名前で）。
- 影の範囲（sun.shadow.camera）を変えたら `updateProjectionMatrix()`。
- r128 の fragment は map_fragment → color_fragment の順。Kit.mat の GLSL は color_fragment のあと。
- 隠れたタブで frame の大きさが 0 → resize で 0 を飛ばす。
- 相関 0.6975 を四捨五入すると 70% なのに判定は「合わない」→ % は切り捨て。
- 「絵を見る大きさ」のボタン群と絵の入れ物が同じ id（view）で、絵の上のボタンを押すと計算の値が NaN になった → ボタン群は `viewDeg`。
- 水は空の映りこみが強すぎて水色になった → `envMapIntensity` 0.45・暗い色。
- Bash の heredoc に長い python を書くと「unexpected EOF」で止まることがある → Write でファイルにしてから実行。
- 窓とかべが1画素ずつまざる（Z ファイティングに見える）→ 本当は instance の整数（aBlind）が補間で 3.9999 になり、窓の有無が画素ごとに入れかわっていた → 丸めてから使う。
- 窓や看板にきらきらした粒 → instance の乱数 vRnd が補間でわずかにずれ、sin×43758 のハッシュで大きく変わっていた → 1/4096 に丸めた値を使う（Kit.mat の #define）。
- Kit.mat の GLSL の最後の行が // の注釈だと、閉じかっこが注釈に入って文法エラー → 閉じかっこの前に改行。
- 本物の町: 地面の canvas を 8192 画素にしたら JS のメモリが 474 MB → 4096／2048 に。形の配列は GPU へ送ったら捨てる（onUpload）→ 560 MB が 132 MB。
- 本物の町: 読みためを捨てるとき、読み終えたばかりで兄弟を待っている子まで捨てて、読む・捨てるをくり返し建物が消えた → 読み終えた時刻を「使った」に。
- 本物の町: 建物がついたり消えたり（ユーザーの指摘）→ ① 子の1つが捨てられると親にもどり、読み直すとまた子へ、をくり返していた → 「描ける」を孫までたどって判定。② 細かくする／粗くもどすの境目でカメラが少し動くたびに入れかわる → もどすのは 0.7 倍まで下がってから。③ 細かくなる手前（0.6 倍）で子を先に読む。カメラを往復させて、3回以上切りかわった建物 0。
- 本物の町が重い（ユーザーの指摘）→ 写真の建物は影の計算から外す・動く物がないときは描き直さない（step が false）・同じ画像の部品を1つにまとめる・部品ごとに画面の外は描かない（範囲は配列を捨てる前に求める）・2.6 km より先は読まない・細かくする目安 24 画素（スマホ 40）。描く回数 1321 → 211、三角形 590 万 → 92 万、1コマ 13 → 9 ms（パソコン）。
- 本物の町: カメラをサンシャイン60 の展望台の位置にしたら塔の中・屋上に入った → 少し西（520 m・25°・向き 80°）。
- 隠れたペインでは requestAnimationFrame が止まり、距離の格子が測られず「この向きでは大きさを出せません」と出る → 確かめは __tish.set({}) で測る。

## 確認のしかた（変更のたびに）
1. `powershell -NoProfile -ExecutionPolicy Bypass -File _dev/tools/smoke.ps1 -Apps tilt-shift`
2. 場面の6つを本物のクリックで切りかえ、絵が出て結果の文が出る（「作っています…」が消える）。目安（最初の設定＝帯・ぼけ 2・帯 10%・位置 0.45、最初の位置、1700×1000 の絵）: 池袋 ≈1/2,900・94%（建物を読み終えてから）、町 ≈1/4,400・70%、駅 ≈1/3,100・94%、港 ≈1/3,750・94%、競技場 ≈1/2,850・93%、海 ≈1/2,400・96%、田んぼ ≈1/4,000・94%。帯をたてにすると「合わない」。町を通常カメラ（ぼけなし）で、手本の写真（look/ref）と同じ角度でくらべる: `tools/shot.mjs` に `"fov":9,"pitch":24,"dist":1500`（名古屋）・`"fov":45,"pitch":40,"dist":450`（池袋）。
3. 絵をドラッグ → 向きが変わる。ホイール／つまむ → 寄る。「もとの位置」でもどる。つまみの「見下ろす角度・向き・はなれる」もいっしょに動く。
4. 止める → 動かない・requestAnimationFrame が止まる。動かす → 続きから。コマ落としで車がカクカク。
5. 幅 393px（iPhone 16）と 375px で、絵と結果が上に固定、横にはみ出さない（scrollWidth − innerWidth = 0）。
6. 裏にして、もどすと続きから（音・Worker・タイマーなし）。

  - 2026-11-23 寄った所・曲がり方・木（ユーザー「寄った場所を詰めたい・車や人が急に向きを変える・木をリアルに・人と車の速さを変えて」）:
    - 曲がり方（roads.js）: 点の手前と先の r を2次ベジェでつなぐ（r は横のずれ＋1.5 m 以上、辺の長さの半分まで）。車は曲がる角度 θ と R = r / tan(θ/2) から √(2R) まで手前で減速。向きは1秒に 1.5（車）・3（人）ラジアンまで。行き止まりの U ターンは、まっすぐ → その場で半円 → まっすぐ。角では横にずれた点がふつうの速さになるよう中心の進みを r / (r + |ずれ|) に。車線の移りもゆっくり。20 秒・約 6,500 体で、1コマの位置の飛び 0。
    - 速さ: 人は平均 1.34 m/s・ばらつき 0.2 の正規分布（Bohannon 1997）、1 割はゆっくり 0.7〜0.9 m/s。車は道の目安の 0.7〜1.3 倍。
    - 木（kit.js）: 樹形の型（広葉樹 5・針葉樹 2、高さ 1）を作って並べる。広葉樹は幹＋3〜4 本の枝＋葉の房 26 個（面の向きは樹冠の丸みと 3:1 でまぜる）、ふちだけ葉のすき間を抜く（本当の面の向きで判定。なめらかな向きで判定すると奥の房が黒く見えた）。型は r / h に近いものを縦横同じ倍率で（引きのばすと面の向きが狂う）。
    - 大きな店の壁: 柱型・ガラスの区画・垂れ幕（店の名前なし）。平らな屋上に室外機を描く。
    - 重さ: 池袋 1,230 万三角形（影を含む）・1コマ 8 ms（パソコン）。木は 6,000 本（スマホ 2,500）。
  - 2026-11-23 ユーザーの指摘6つ:
    - 地面のちらつき: 道・歩道・芝の重なりは数 cm の浮きでは遠くで深さの精度が足りない → polygonOffset で層の順（streets.js の add の layer）。白線・目地は fwidth で画素より細いときは薄さで出す（aaL・aaJ）。
