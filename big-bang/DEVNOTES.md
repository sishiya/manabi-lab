## しくみ
- 単位は AU・年・太陽の重さ（G = 4π²）。太陽は原点に止めて置く。1歩 DT = 1/256 年、リープフロッグ（半分けり→進む→重力→半分けり）。
- 岩1つ = 64 バイト（p: 位置・重さ／v: 速さ・半径 AU／a: 加速度・岩どうしの位置エネルギー／e: 比エネルギー J/kg・_・番号）。重さ 0 = 空き。
- 重力は全部の組を足す（64 個ずつ共有メモリ）。同じ回り道で「この1歩のあいだにいちばん近づいた相手」をさがす（相対速度で1歩さかのぼって最も近い距離。`cut2` より遠い組は調べない）。おたがいに相手どうしの組だけぶつける。
- ぶつかり: ふれる距離 = F ×（半径の和）。F 倍の所から本当の表面まで落ちる分の速さを足して v_imp²。v_imp < 逃げる速さ → くっつく。速いと Leinhardt & Stewart 2012（式28 Q*_RD,γ=1 = c*·(4/5)πρ₁GR_C1²、式23 で重さの比、式5 で M_lr/M_tot = 1 − 0.5 Q_R/Q*_RD、1.8 をこえたら 0.1·(1.8/x)^1.5（この形は推定。論文の式44は読み切れていない））。c* = 1.9、μ̄ = 0.36（惑星くらいの当てはめ）。正面衝突として角度の補正なし。
- かけら: 残りの重さを mMin（はじめの岩の半分）以上の同じ重さで最大 8 個。立方体の角の向きをでたらめに回して ± の組で置く（勢いの合計が変わらない・たがいに重ならない）。距離 1.2F（R_lr + 2R_f）。かけらの動きのエネルギーは「d で逃げる速さの 1.2 倍に要る分」と「ぶつかるエネルギーの 3 割」の大きいほう（推定）。残りが熱。空きの席は1コマのはじめに作る一覧（freeReset・freePush）から atomic で取る。席がなければ「ちり」。
- 熱: 比熱 1000、1500 K でとける（40万 J/kg）、3000 K で蒸発（1000万 J/kg）。どれも推定。とけている間は表面から σT⁴（ふたなし）、固まったら R²/(π²κ)（κ = 10⁻⁶ m²/s）で冷える。アルミニウム26 は 1.9×10⁻⁷ W/kg ×exp(−t/1.034 百万年)（26Al/27Al = 5×10⁻⁵、Al 1.13%、3.12 MeV から計算）。熱は1コマに1回（1歩ぶんの増えは f32 の目より小さいことがあるため）、小分け（最大 24 回、まわりの温度までの残りの 1/4 ずつ）。
- 近くで（はじめの見方）: 半径 A0 = 1 AU の円軌道と同じ角速度で回るカメラ（画面の右 = 回る向き、上 = 太陽から外）。短い辺の半分 = 0.25 AU。時間は 1コマ 0.4／1.25／4 歩（ゆっくり／ふつう／はやく。端数はためる）。内側の岩は右へ、外側は左へ流れる（ケプラーのずれ）。「全体」は止まったカメラで GPU の速さぶん進める。描画のシェーダーは画面の右・上の向き（View.hi）で回す。
- 指: 輪（80 px）の中の岩を「指そのものの速さ（近くで: カメラといっしょに回る速さ、全体: その場所の円軌道の速さ）＋指の動き」にそろえ、さらに指の真ん中（円盤の面 z = 0 の上）へ一定の速さ vEdge で引きよせる（τ = 0.01 年）。vEdge = 0.1 + 0.3 × 指の速さ（AU/年、1.2 まで）。指の速さは「画面で動いた距離 ÷ 計算の中で進んだ時間」（指は計算の中の物）、上限 6.3 AU/年。した仕事を atomic で数えて「指が足したエネルギー」（はじめの公転のエネルギーに対する %）。画面には「寄せる速さ」= 2 × vEdge（km/s）。
- ぶつかった所: collide が EV（256 個、数は C[10]）に x, y, 種類, 残った割合を書き、読み出しのたびに view.js が印（緑の輪 = くっついた、オレンジの線 = 砕けた。1.6 秒）と文字（近くで、新しい 4 つ）を描く。「くっついた」= 残りが2つの大きいほうより重い（論文の部分的にくっつく）、「砕けた」= 軽い（削られた）。
- 数え（i32 の atomic）: ちり・太陽へ・とび出しは 10¹⁵ 倍、仕事は 10¹²、熱は 10¹³。読み出しのたび（4コマに1回）に 0〜8 番を 0 にもどす（9 空き・15 歩の通し番号は残す）。
- 粒の数: 起動時に 1024 から倍々で重力1回の時間をはかり、2.2 ms 以内のいちばん多い数（スマホは 4096 まで）。1コマの歩数は「ふつう」8 ms・「はやく」14 ms に入る数。

## ハマったところ
- 粒が少ないと GPU の一部しか働かない（256 個ずつだと 8192 個で 32 グループ）。重力だけ 64 個ずつにした。
- かけらを でたらめな向きに置くと、かけらどうしが重なって次の歩でくっつく → 立方体の角の向きに。
- 指を「画面の上の速さ」そのままにすると、止めた指がブレーキになって岩が太陽へ落ちる（60%）／速くなでると全部とび出す（70%、エネルギー +1100%）→ 円軌道の速さを足し、上限をつけた。
- 蒸発する熱を入れないと 10 km/s の衝突で 7000 K、30 km/s で 10万 K → 蒸発（3000 K）を足した。とても熱いかけらは1コマで冷えすぎて 0 K になった → 小分けにして下限をつけた。
- F を大きくすると「逃げる速さより遅い」がほとんど起きない（v_imp² = w² + v_esc²(1 − 1/F) なので）。かわりに 9 割より多く残る衝突は「くっつく」と数える。
- このPCでは Blender など ほかの GPU の仕事があると速さが大きく変わる（自動の数が 4096〜16384 でゆれた）。

- 「近くで」で岩がほとんどぶつからなかった。原因は3つ: (1) 岩の間かくが ふれる距離の 300 倍（本物の宇宙はすかすか）→ 指で寄せることにした、(2) 輪の中の岩が指からずれていく（内と外で回る速さがちがう）→ 指そのものの速さにそろえる、(3) 上から見て重なっても 上下（円盤の面からのずれ、ふれる距離の 30 倍）で離れていた → 上下も寄せる。さらに、真ん中で寄せる速さをゆるめると速く動かしても やさしくぶつかるだけ → 真ん中まで同じ速さに。指の速さを固定の倍率で決めると、時間がゆっくりな「近くで」では指に岩がついてこない → 計算の中の時間で割る。

## 確認のしかた（変更のたびに）
1. `node big-bang/tools/verify.mjs all`（ケプラー 1000 周のエネルギー・ぶつかりの重さと勢い・かけらが離れていく・冷え方・512 個の円盤で重さが保たれる）
2. GPU つきのヘッドレス Chrome か、見えている Browser ペインで: エラー 0（`__bibaErr`）、`await __biba.testGpu()` で GPU と JS が合う（ぶつからない 256 個 64 歩の位置の差 < 1e-5 AU、正面衝突の個数・重さ＋ちり＝1・勢い）。
3. 「近くで」: 指で押さえて 3〜4 秒 → 輪の真ん中に岩が集まり、緑の「くっついた」が出て、いちばん大きい岩が何十倍にも育つ。速く動かす → 寄せる速さが オレンジ（秒速 1.5 km 超え）になり、「砕けた」・熱い岩も出る。「全体」に切りかえられる。「つぎへ」で 7 段（6 段目に光る輪）。
4. 幅 375px: 横にはみ出さない（scrollWidth 375）、図とひとことが上に固定。
5. `powershell -NoProfile -ExecutionPolicy Bypass -File _dev/tools/smoke.ps1 -Apps big-bang`（swiftshader なので「WebGPU が使えない」画面の確認になる）
