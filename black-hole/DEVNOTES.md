# ブラックホールの見え方 開発メモ

最終更新: 2026-10-08

映画「インターステラー」のブラックホール（円盤が穴の上と下にも回り込んで見える姿）を、回るブラックホール（カー時空）のまわりの光の道すじを本当に計算して描き、なぜあの形に見えるのかを、クリックした点の光の道すじの図で確かめるアプリ。企画は `PLAN.md`。WebGL2 直書き（ライブラリなし）。

## 別セッションで続けるとき（まずここ）
- **いまの状態**: v1（`versions/v001-first`）＝段階A。入口「まなびラボ」・隠しアーカイブには**まだ載せていない**。Artifact にも公開していない（GA の1行・サムネイルもまだ）。
- **次にやること**: ユーザーの感想しだい。入口かアーカイブに載せるなら RULES 8.1（GA の1行・サムネイル `thumbs/black-hole.jpg`・`tools/thumb.html` の `SETUP`・`APPS` か `archive.html` のカード・互換モードの確認）。次の段階は `PLAN.md` の段階B（円軌道を回るカメラ・落ちていくカメラ・探査機・ミラーの星）、C（EHT の写真と比べる）。
- **読む順**: `../RULES.md` → このファイル → 下の「ファイル構成」で関係するファイルだけ。
- **動かし方**: `.claude/launch.json` の空いているサーバーで `http://localhost:<port>/black-hole/`（2026-10-08 は 8765 が Windows の予約で使えず、`apps-6`＝8770 を使った）。
- **デバッグ用**: `window.__bh` — `S`（状態）、`R`（WebGL の段 `R.levels.low/high`）、`renderNow(時刻?)`（Browser ペインが裏だと rAF が止まるので、これで細かい段まで描き切る。`true` が返れば完了）、`pickAt(nx, ny)`（画面の点 −1〜1 の光をたどって図と説明を出す）、`traceRay(cam, N, a, disk)`、`camDir(nx, ny, aspect, tanF, look)`、`readGeo(nx, ny, 'high'|'low')`（GPU の結果 `[種類, r, φ, g]`。種類 0 = 穴、1 = 円盤の上の面、1.5 = 下の面、2 = 空で残りは方向）、`set({...})`（状態を変えて描き直し）、`applyPreset('movie'|'side'|'tilt'|'top')`、`setSpin(a)`、`err`（例外。`window.__bhErr`）。
- **ペインが隠れているとき**: 画面の大きさが 0 になって何も描けない。`resize_window` で大きさを指定（例 1280×760）してから読み直し、`__bh.renderNow()`。
- **区切りごとに**: ① `versions/v0NN-名前/` に index.html・css・js を丸ごとコピー ② `launcher.html` にカード・表 ③ 下の「状態」 ④ 「確認のしかた」を通す ⑤ 公開前チェック → コミット（push はユーザー）。
- **ユーザーの好み**: 正確さ重視（数値の出どころ・簡単にしたところを画面に書く）。眺めるだけでなく手で動かせること（ここではクリックで光の道すじ・ドラッグで回る）。子どもにも読める日本語。

## しくみ

### 1. 式（`kerr.js` と `GEO_FS`）
- 単位は G = c = M = 1。ボイヤー・リンキスト座標 (r, θ, φ)。光は p_t = −1 にそろえ、保存量 b = L/E とカーターの定数 q = Q/E²。
- 運動の式（時間の向き。逆にたどるので歩幅 h は負）: Σ = r² + a²cos²θ、Δ = r² − 2r + a²、P = r² + a² − ab、K = (b − a)² + q、R = P² − ΔK。
  dr/dλ = Δp_r/Σ、dθ/dλ = p_θ/Σ、dφ/dλ = (aP/Δ − a + b/sin²θ)/Σ、dp_r/dλ = (R′/Δ − RΔ′/Δ² − Δ′p_r²)/(2Σ)（R′ = 4rP − Δ′K、Δ′ = 2r − 2）、dp_θ/dλ = (b²cosθ/sin³θ − a²sinθcosθ)/Σ。H = 0（光）を使って ρ² の微分の項を消した形。自分で導いたが、James ほか 2015 の付録 A と同じ形（論文は φ の符号が逆。論文の ζ は時間を逆にたどる向きのため）。
- カメラは ZAMO（その場所で空間の引きずりと一緒に回る観測者）。向き: 前 = −r̂、上 = −θ̂（北）、右 = φ̂。光の進む向き n = −N から E_F = 1/(α + ωϖn_φ)、p_r = E_F ρ/√Δ n_r、p_θ = E_F ρ n_θ、b = E_F ϖ n_φ、q = p_θ² + cos²θ(b²/sin²θ − a²)。
- 円盤の点の振動数のずれ g = E_F / (u^t (1 − Ω b))、Ω = 1/(r^{3/2} + a)、u^t = (r^{3/2} + a)/(r^{3/4}√(r^{3/2} − 3r^{1/2} + 2a))（BPT 1972）。左（こちらへ回ってくる側）で約 1.36、穴の上の帯で約 0.76（映画の角度・a = 0.6）。
- 歩幅: 0.06 (r − r₊)、最小 0.004。**さらに 1 歩の |Δφ| + |Δθ| が 0.04 rad を超えないように縮める**（回転軸の近くを通る光のため。下の「ハマったところ」）。終わり: r < r₊ + 0.01 で穴、赤道面をまたいで rin ≤ r ≤ rout で円盤（上からなら上の面）、r > max(2 r_cam, 60) で外向きなら空（最後の 1 歩の向き）、900 歩で終わらなければ穴（光の円軌道のまわりを回り続ける光）。
- 円盤: 内側 = ISCO（a = 0.6 で 3.83M）、外側 18.7M（論文の図 13 の 18.70M）。光を通さない板。

### 2. 描画の段（`render.js`・`main.js`）
- `low`（画面の約 16 万ピクセル）: カメラが動くたびに一度に光をたどる。`high`（画面 × 2 倍の細かさ、上限 500 万ピクセル。縮めてふちをなめらかに）: 止まって 140 ms たったら、192 px のタイルを真ん中から順に、コマの時間に合わせた枚数（`R.budget`）ずつ。
- カメラの φ（左右のドラッグ）は空と円盤の模様を回すだけ（軸のまわりで同じなので、光をたどり直さない）。θ・距離・回転・円盤あり／なしでたどり直す。
- 色づけは毎コマ: 円盤の模様は (r, φ − Ω t) の値ノイズ（ケプラー回転）。時間は 1 秒 = 8M（Gargantua なら約 66 分、実際の約 4000 倍）。
- 映画版: 色温度 2900 + 2300 x^−1.2 K（x = r/rin）、明るさ x^−1.6。本当の見え方: 温度の形はシャクラ・スニヤエフ（F ∝ r^−3(1 − √(rin/r))）で最高 5200 K（見やすさの目安）、色温度 × g、明るさ × g⁴。明るさの調整は `lookParams`（diskGain 映画 1.8・本当 0.32、ブルーム 0.55・0.5）。
- 空のぼかし: となりのピクセルの方向との角度から mip の段を決める（`textureLod`。正距円筒のつなぎ目で線が出ないように、自動の微分は使わない）。

### 3. 光の道すじの図（`ui.js`）
- クリックした点を CPU（`traceRay`、倍精度・最大 4000 歩）でたどり、`toXYZ`（x がカメラの方向、z が回転軸）で横から（x–z）・上から（x–y）に描く。全体／穴の近く（±8M）。矢じりは光の本当の進む向き（源 → カメラ）。
- 説明（`describeRay`）: 穴（影）、円盤の手前／向こう側（当たった所の x の正負）・上の面／下の面、曲がった角度（向きの変化を足し合わせたもの。180° を超える）、穴にいちばん近づいた所。本当の見え方では g と g⁴。

### 4. 映画の角度での見え方の確かめ（a = 0.6、r = 28、θ = 85°、縦の視野 50°。画面の真ん中の縦の線上、上から）

## ハマったところ
- **真ん中の縦の線**: 画面の真ん中の列は b ≈ 0（回転軸の真上・真下を通る光）。sinθ が小さい所で dφ/dλ = b/sin²θ が大きくなり、歩幅が大きいと計算が荒れて、縦にちらつく線が出た → 1 歩で回る角度に上限（0.04 rad）。
- **回転軸をまたいだ光**: b = 0 ちょうどの光は θ が負（または π 超え）になる。当たった所を θ = π/2 で計算すると手前と向こう側が逆になった → 道すじの点を補って位置を出す（`hitXYZ`）、シェーダーでは sinθ < 0 なら φ + π。
- **星が弧のように伸びる**のは正しい: r = 28 ではアインシュタインリングの半径が約 22°（√(4M/r)）と大きく、画面のほとんどがその近く。遠く（r = 300）では星は丸い（確かめた）。
- **真上から見たとき**、円盤の内側（ISCO）の像が影にくっつき、下の面の像（2 番目の像）は見えない。見つけてみようの文はそれに合わせた。
- 影の中の灰色のもや: ブルームのしきい値 0.6 では影にかかりすぎた → 0.9。
- Browser ペインが隠れていると画面の大きさが 0（何も描けない）。`resize_window` で大きさを指定する。

## 確認のしかた（変更のたびに）
コンソールエラーがなく（`__bh.err` が空）、次ができること。
1. 開いたとき（映画の角度）: 穴の上と下に円盤の帯、真ん中の縦の線がない（スクリーンショットで）。
2. GPU と CPU が合う: `__bh.renderNow(); __bh.readGeo(0.04, 0.5)` が `[1, 約6.8, 約3.0, 約0.76]`、`__bh.pickAt(0.04, 0.5).rHit` も約 6.8。
3. クリック: 穴の上の帯 → 「円盤の向こう側・上の面」、下の帯（`pickAt(0.03, -0.5)`）→「向こう側・下の面」、影のふち（`pickAt(0.03, 0.392)`）→ 曲がった角度 180° 以上。図の「横から／上から」「全体／穴の近く」が切りかわる。
4. 本当の見え方: 左が明るく右が暗い。回転 0.99・真横・円盤なし・方眼で、影が右へずれて左側が平らになる。真上・近づく（r < 6）で見つけてみようが出る。
5. ドラッグ: 上下でカメラの緯度、左右で空と円盤が回る（光はたどり直さない）。ホイールで近づく。
6. スマホ表示（`resize_window` mobile）で図が上に固定され、横にはみ出さない。
   ```js
   __bh.renderNow(); [__bh.readGeo(0.04,0.5), __bh.pickAt(0.04,0.5).kind, __bh.err]
   ```
